# KMP 枠

upload ログからの deployment ID 抽出 (workflow と同じ正規表現):
  $ grep -oiE 'deployment id: [0-9a-f-]{36}' <upload log> | tail -n 1 | awk '{print $3}'
  <uuid>
→ 抽出できた。ログの行の形は翻案元と同じ。

central-portal.sh の応答 (順に status / wait-validated / drop / status):
  $ scripts/release/central-portal.sh status <uuid>
  VALIDATED
  $ scripts/release/central-portal.sh wait-validated <uuid>
  VALIDATED
  $ scripts/release/central-portal.sh drop <uuid>
  drop した (VALIDATED): <uuid>
  $ scripts/release/central-portal.sh status <uuid>
  NOT_FOUND

確認できたこと:
  - KMP の 5 publication (cinterop klib・SwiftPM 連携メタデータ JSON を含む) が署名つきで
    Portal の検証を通り VALIDATED になる (upload 後に自動公開されない = 3.0 の裏取り)
  - status / wait-validated の状態語、drop の成功、drop 後の NOT_FOUND が
    スクリプトの契約 (冒頭コメント) どおり
  - 発行タスク名 publishToMavenCentral と -Pversion= の注入で 1 deployment が作られる
