# 実装乖離メモ: add-verification-ci

- Requirement「ツールチェーンの再現性」/ proposal Non-Goals「`samples/maui` の CI ビルドと `MauiVersion` の変更」: spec では Sample の `MauiVersion` は変えず、解決版が推移的に 10.0.70 へ上がる想定 → 指示により `samples/maui/KsDialogs.Sample.Maui/KsDialogs.Sample.Maui.csproj` に `<MauiVersion>10.0.70</MauiVersion>` を明示する (参照は `$(MauiVersion)` 経由のまま)。理由: Sample が版を持たないと workload set 既定の 10.0.20 が入り、NuGet は推移参照の上位版へ持ち上げないため NU1605 で restore が失敗する (実測)。翻案元 KsSettingsView の Sample も同じ形で 10.0.70 を明示している。Sample を CI で組まない点は変わらない (2026-09-08)
- Scenario「metadata compile の失敗を検出する」/ tasks 5.4: spec では「ターゲット本体のコンパイルは通るが metadata compile だけが失敗する変更」を作って確認する → 現行 Kotlin (2.4.x) では iosMain の `@Throws` override をターゲット本体の compile が先に検出するため、その状態を構成できなかった。job のコマンド全体が失敗すること、`compileIosMainKotlinMetadata` 単体が同じ違反を検出することの 2 点で機構を確認した (evidence/ci-step-negative-cases.md 5.4)。理由: 過去に metadata compile だけを壊した Kotlin 2.4.10 の既知バグ (KT-88548) が現行の構成では再現しない (2026-09-08)
- Requirement「platform workflow の再利用契約」/ Scenario「status check 名が固定される」: spec では status check 名を 6 件と書いている → 変更検出 job (`changes`) が 7 本目の check として報告される (GitHub は job ごとに check run を作る)。必須 check として固定するのは 6 件のままで、`changes` は補助 check。理由: `paths-ignore` を撤去して変更検出を job に移した結果 (相方 spec レビュー #1 の採用による)。phase-9 の必須 check 一覧に「`changes` は必須に含めない」を申し送る (2026-09-08)
