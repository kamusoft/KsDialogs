- design Decision 4 (2) / Decision 5 の 3 段 (2) / tasks 1.4・3.1「`linkReleaseFrameworkIosSimulatorArm64` で linkage package を再生成する」: spec では link タスクが linkage package を再生成する → 実測 (evidence/premise/1.4 観測 4) により link タスクは linkage package を生成も更新もしない。再生成は環境変数 `XCODEPROJ_PATH` を与えた `generateSyntheticLinkageSwiftPMImportProjectForLinkageForCli` (`integrateLinkagePackage` の依存タスク) が担うため、消費者ビルドの 2 段目は「作業コピー内で同タスクによる再生成 → link タスクで framework 生成」の 2 手で構成する。作業コピーで再生成するという判断 (Decision 4) と 3 段の順序 (Decision 5) は変えない。理由: 前提の実測で覆った (tasks 1.5)。判断の骨格が変わらないためオーケストレーターが記録して続行 (2026-09-09)
- Decision 4 の追跡物の所在: spec では linkage package の Swift 参照はルートの `Package.swift` にある前提の記述 → 実測により Swift 参照は `KotlinMultiplatformLinkedPackage/subpackages/jp_kamusoft_ksdialogs_kmp_<version を _ 区切りにしたもの>/Package.swift` にあり、subpackage ディレクトリ名に version を含む。追跡する smoke 形は検証用の既定 version (`0.0.0-alpha.0`) の subpackage 名で置き、3.4 の検査は subpackage 側の manifest を読む。理由: 同上 (2026-09-09)
- tasks 1.2 の負ケースの失敗コード: tasks では NU1101 → 実測は NU1102 (パッケージ ID は mapping 先に在り version だけが無いため)。Scenario「ローカル参照先に無ければ公開済みの版でも失敗する」の判定は満たす。理由: 例示の相違のみ (2026-09-09)
- Scenario「追跡している生成物は実行で変化しない」/ design Decision 4 / tasks 3.1・5.1: spec では作業コピーへの退避で守る追跡物は `verification/kmp/` のみ → 実測 (evidence/premise/1.5) により kmp/ のリリース版発行が本体側の合成 Swift マニフェスト 2 本 (`kmp/.swiftpm-locks/default/swiftImport/subpackages/_ksdialogs-kmp/Package.swift`・`_ksdialogs_kmp/Package.swift`) を `file://` の絶対パスへ書き換えるため、KMP のフィード準備 (`verification/lib/gradle-publish.sh` の kmp/ 発行) は、発行前にこの 2 本が HEAD から未変更であること (Git 管理下・追跡済み・作業ツリーと index に差分なし) を検査して変更済みなら発行せず失敗し、発行の成否によらず `EXIT` trap で `git checkout HEAD --` により復元する (呼び出し元の EXIT trap は控えて連結)。5.1 の `git status` 確認範囲に `kmp/.swiftpm-locks/` を含める。理由: 手元実行のたびに identity lint に掛かる状態が作業ツリーに残るのを避ける (オーナー判断 A、2026-09-09。復元の機構は review-001 / second-opinion-code-001 の指摘で発行後の単純復元から現行へ改めた)
- Scenario「KMP のホスト側は利用者向け手順の 3 点だけを参照する」/ tasks 2.5 の「`VerificationApp` の Swift ソースは登録例に倣い `ConfirmViewModel` を登録して show を呼ぶ」: spec ではローカル Swift package が登録 API を呼ぶ → 実装では共有モジュールの framework (`VerificationShared`) が Xcode のアプリ target にしか届かず SwiftPM の package target から共有 ViewModel 型を import できないため、登録と show はアプリ target (`iosApp/VerificationKmp/KmpDialogRegistration.swift`) に置き、ローカル package `VerificationApp` は配布物の公開面 (`@_exported import KsDialogs`) と View (`ConfirmContent`) を持つ。参照 3 点 (framework / 合成 package / ローカル package) の構成と、登録 API を消費者ソースから呼ぶことは変わらない。concepts kmp/api/ios-host-integration.md と Sample も登録をアプリ側に置いている。理由: 技術制約 (実装ワーカーの観測、オーケストレーター判断で記録、2026-09-09)
