# 5.5 `main` 宛ての draft PR での CI 起動 (2026-09-09)

対応 Scenario: main 宛ての PR で起動する / develop への push で本体検証と lint が起動する /
消費者検証は dry-run で動く / 解決版と取得元が読める / 配信先への書き込み経路を持たない /
status check 名が固定される

## 前提 (deviation 参照)

リモートに `main` は無かった (cross/ADR-0016: 初回リリースの PR で作る)。実装前の commit 36ed37c から
一時的に `main` を作成 (オーナーが push)、develop → main の draft PR #1 を作成。確認後に PR をクローズし
`main` を削除する。branch protection は付けていない。

## 観測 1: `develop` への push (cfa6033 / ef3daba) — 消費者 4 job は起動しない

  run (push, develop): changes / lint 成功、consumer-ios / -android / -kmp / -maui は skipped、
  本体 5 job (ios / android / android-instrumented / kmp / maui) は実行。lint job の README 一致検査
  (8 検査目) も通過。

## 観測 2: `main` 宛て draft PR #1 — 消費者 4 job が起動し成功 (run 34357952236、ef3daba)

status check 名 (ci.yml 冒頭コメントの 10 件と一致):

  maui / verify / consumer-ios / verify / consumer-android / verify / consumer-maui / verify /
  consumer-kmp / verify
