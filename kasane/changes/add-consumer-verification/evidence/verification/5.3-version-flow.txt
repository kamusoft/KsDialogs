## 見つかった不具合と修正

最初の実行 (`--version 0.1.0-rc.1`) は 3 段のビルドがすべて成功したあと、依存検査が
例外で落ちた。

  LookupError: 合成 package の subpackage が 1 つではありません: 2 件
               (<work>/kmp/consumer/iosApp/KotlinMultiplatformLinkedPackage)

  $ ls <work>/kmp/consumer/iosApp/KotlinMultiplatformLinkedPackage/subpackages
  jp_kamusoft_ksdialogs_kmp_0_0_0_alpha_0     (追跡している fixture を写したもの)
  jp_kamusoft_ksdialogs_kmp_0_1_0_rc_1        (2 段目の再生成が作ったもの)

合成 package の subpackage はディレクトリ名に version を含むため、追跡している fixture の
version (`0.0.0-alpha.0`) と実行の version が違うと、作業コピーに写した古い方が残って
2 つになる。ルートの manifest は再生成後に新しい subpackage だけを参照しており
(`.package(path: "subpackages/jp_kamusoft_ksdialogs_kmp_0_1_0_rc_1")`)、ビルドは通るが、
検査が Swift 参照を持つ manifest を 1 つに特定できない。

修正: `verification/kmp/build-consumer.sh` の作業コピー (rsync) から
`iosApp/KotlinMultiplatformLinkedPackage/subpackages/` を除外する。この subpackage は
2 段目の再生成が作り直すもので、写す必要がない。

再実行で依存検査まで成功 (上の表)。既定 version (`0.0.0-alpha.0`) の dry-run も
修正後に再実行して成功し、`verification/kmp/` の追跡物に差分は出ない。
