# 1.3 Android / KMP のフィード隔離 (2026-09-09)

判定: **成立**

## 観測 1: 発行先は作業ディレクトリのみ (`~/.m2` を汚さない)

実行前に `~/.m2/repository/jp/kamusoft` 配下のパス一覧を取得 (82 行。phase-6 / phase-7 の
残留物として `ksdialogs-core` `ksdialogs` の `0.1.0-SNAPSHOT`、`ksdialogs-kmp` 系の `0.1.0`
が既に置かれている)。

$ ./gradlew -Pversion=0.0.0-alpha.0 \
    -Dmaven.repo.local=<scratch>/premise/maven publishToMavenLocal   (実行場所: android/)
BUILD SUCCESSFUL in 9s

`<scratch>/premise/maven/jp/kamusoft/` 配下 (version はすべて `0.0.0-alpha.0`):

  ksdialogs-core/  .aar / .pom / .module / -sources.jar / -javadoc.jar
  ksdialogs/       .aar / .pom / .module / -sources.jar / -javadoc.jar

実行後の `~/.m2/repository/jp/kamusoft` の一覧は実行前と完全一致 (diff 0 行)。
`-Dmaven.repo.local` がローカル発行先の指定として効いている (design Decision 2 の前提)。

## 観測 2: 署名鍵の無い環境で Sign が skip される

$ grep "signMavenPublication" <発行ログ>
> Task :ksdialogs:signMavenPublication SKIPPED
> Task :ksdialogs-core:signMavenPublication SKIPPED

リリース版形式の version (`0.0.0-alpha.0`) でも失敗せず未署名のまま通る。

## 観測 3: 消費者が exclusiveContent で解決できる

消費者 `<scratch>/premise/android-consumer` は `com.android.application` 1 module
(`applicationId` `jp.kamusoft.ksdialogs.verification.android`、compileSdk / minSdk は
`android/gradle/libs.versions.toml` の値)。`settings.gradle.kts` は
`exclusiveContent { forRepository { maven { url = uri("<scratch>/premise/maven") } }
filter { includeGroup("jp.kamusoft") } }` に加えて google / mavenCentral を持ち、
version catalog は本体の `android/gradle/libs.versions.toml` を共有する。
ソースは README `### Android Native` の最小例を無編集で置いた。
Android SDK は本体 `android/local.properties` の `sdk.dir` を `ANDROID_HOME` に export して渡した。

$ ./gradlew -Pksdialogs.version=0.0.0-alpha.0 :app:dependencies --configuration releaseRuntimeClasspath
+--- jp.kamusoft:ksdialogs:0.0.0-alpha.0
|    +--- jp.kamusoft:ksdialogs-core:0.0.0-alpha.0

$ ./gradlew -Pksdialogs.version=0.0.0-alpha.0 :app:assembleRelease
BUILD SUCCESSFUL in 25s

## 観測 4: フィードに無い version は Central を検索せずに失敗する

`0.1.0` (フィードに無い。公開もされていない) を指定して同じ消費者をビルドする:

$ ./gradlew --info -Pksdialogs.version=0.1.0 :app:assembleRelease
> Could not find jp.kamusoft:ksdialogs:0.1.0.
  Searched in the following locations:
    - file:<scratch>/premise/maven/jp/kamusoft/ksdialogs/0.1.0/ksdialogs-0.1.0.pom
BUILD FAILED

検索先はローカル参照先 1 つだけ。`--info` の全出力を通しても
`repo1.maven.org` / `repo.maven.apache.org` / `dl.google.com` へ `kamusoft` 座標を
問い合わせた行は 0 件。`~/.m2` にも問い合わせない (リポジトリに宣言していないため)。

注: `:app:dependencies` は解決失敗を `FAILED` と表示するがビルド自体は成功で終わる。
負ケースの判定にはビルドタスク (`assembleRelease`) を使う必要がある。

## 付随して分かったこと (グループ 2 への申し送り)

`com.android.application` の module は `src/main/AndroidManifest.xml` が無いと
`processReleaseMainManifest` が「Input file does not exist」で失敗する
(namespace 指定だけでは生成されない)。verification/android の 2 module には
最小の manifest を置く必要がある。
