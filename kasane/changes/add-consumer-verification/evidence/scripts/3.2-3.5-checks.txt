## 3.2 Android の依存検査 (build-consumer.sh 内)

`:app` と `:app-core` の `releaseRuntimeClasspath` の依存ツリーから判定する。版が競合した
ときの Gradle の表記 (「宣言 -> 解決」) は解決側を取る。

  ==== 解決版と取得元 ====
  参照先: <scratch>/work/ksdialogs-verification/android/maven

  :app (releaseRuntimeClasspath の jp.kamusoft 行)
  +--- jp.kamusoft:ksdialogs:0.0.0-alpha.0
  |    +--- jp.kamusoft:ksdialogs-core:0.0.0-alpha.0

  :app-core (releaseRuntimeClasspath の jp.kamusoft 行)
  \--- jp.kamusoft:ksdialogs-core:0.0.0-alpha.0

  :app-core の androidx.compose 座標: 0 件
  ksdialogs と推移の ksdialogs-core が 0.0.0-alpha.0 で一致し、-core 単独の消費者に
  androidx.compose は無い

依存ツリーの取得は Gradle の失敗と「行が無い」を区別する (ツリーをファイルへ受けてから
判定し、失敗時はツリーの内容を標準エラーへ出す)。

  全 5 publication と ksdialogs-core が 0.0.0-alpha.0 で解決され、Swift 参照は
  合成 package・ホスト側・発行 metadata で一致し、pin は 1 つ

合成 package の Swift 参照は subpackage 側のマニフェストにある。検査は
`KotlinMultiplatformLinkedPackage/subpackages/*/Package.swift` がちょうど 1 件であることを
要求して、その 1 件を読む (version が名前に入るディレクトリ名を組み立てない)。

metadata の検査は参照先がローカルのディレクトリのときだけ行う (smoke は公開レジストリを
参照するため metadata を読めない。その旨を出力に出す)。
