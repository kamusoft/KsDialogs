# loading-contract デルタ (wait-for-host-appearance)

Scenario ID は `LD-HW-<NN>` (提示先の出現待ち)。挙動は Native 2 実装 (iOS / Android) の同名テストで全量を検証する (core/ADR-0016)。Android はすでにこの挙動を持つので、Android では既存の振る舞いを ID つきのテストで固定する。決定の出典は core/ADR-0039 (proposed)、実現経路は design Decision 1・2。

既存の「提示環境が無くても action は実行される」(LD-CO-14) は変えない。本書は、開始時点で提示先が無かった表示の「その後」の定めの追加分。

## ADDED Requirements

### Requirement: 提示先が無いまま始まった Loading の表示

開始時点で提示先が無かった Loading は、処理を通常どおり実行したまま、提示先の出現を待つ SHALL。

- 提示先が現れた時点で表示が続いていれば (合流が終わっておらず、閉じられてもいなければ)、中身を作り、入りのフック (presentation) を経て表示する
- 提示先が現れる前に表示が終われば (合流の最後の終了、または hide)、何も表示せず、待ちもやめる

中身を作る時点は次のとおりとする SHALL。

- 開始時点で提示先があれば、開始時点で作る。中身の生成の失敗は開始の失敗として呼び出し元へ返る (今までどおり)
- 開始時点で提示先が無ければ、提示先が現れた時点で作る。この生成に失敗した場合は、警告ログを残して表示だけを諦める。合流状態は残り、処理はそのまま続いて結果を返す。失敗は呼び出し元へ返さない
- どちらの場合も、View factory の登録の解決は開始時点で行う。未登録の ViewModel 型は、提示先の有無にかかわらず開始の失敗になる (構成ミスは今までどおり呼び出し元へ返る)

開始時点で提示先が無くても、カスタム View の VM (進捗の受け口) は開始時点で控える。そのため、表示の前に報告された進捗も VM の受け口へ届く SHALL。

#### Scenario: [LD-HW-01] 提示先が現れた時点で処理中なら、入りのフックを経て表示される
- **GIVEN** 提示先が無い状態で始めた Loading (スコープ形) と、完了を外から制御できる action
- **WHEN** action の実行中に提示先を出現させる
- **THEN** その時点で中身が作られ、入りのフックが呼ばれて Loading が表示される。action が終わると Loading は閉じ、スコープ形は action の戻り値を返す

#### Scenario: [LD-HW-02] 提示先が現れる前に処理が終われば、何も表示されない
- **GIVEN** 提示先が無い状態で始めた Loading (スコープ形)
- **WHEN** action が終わってから提示先を出現させる
- **THEN** スコープ形は action の戻り値を返し、提示先が現れても中身は作られず、Loading は表示されない

#### Scenario: [LD-HW-03] 提示先が現れる前に hide されれば、何も表示されない
- **GIVEN** 提示先が無い状態で show した Loading
- **WHEN** hide を呼んでから提示先を出現させる
- **THEN** 中身は作られず、Loading は表示されない

#### Scenario: [LD-HW-04] 提示先が現れた時点の中身の生成に失敗すると、表示だけを諦めて処理は続く
- **GIVEN** 提示先が無い状態で始めた Loading (スコープ形) と、呼ばれると失敗するカスタム View の factory
- **WHEN** action の実行中に提示先を出現させる
- **THEN** 警告ログが残り、Loading は表示されない。action はそのまま続き、スコープ形は action の戻り値を返す (失敗は返らない)

#### Scenario: [LD-HW-05] 表示の前に報告した進捗も VM の受け口へ届く
- **GIVEN** 提示先が無い状態で始めた、進捗の受け口を実装した VM のカスタム Loading
- **WHEN** 提示先が現れる前に進捗を報告する
- **THEN** 報告した進捗が VM の受け口へ届く

#### Scenario: [LD-HW-07] 提示先が無くても、未登録のカスタム Loading は開始の時点で失敗する
- **GIVEN** 提示先が無い状態と、View factory が未登録の ViewModel 型
- **WHEN** その ViewModel でカスタム Loading を始める
- **THEN** 開始が構成ミスの失敗として呼び出し元へ返り、action は実行されない

#### Scenario: [LD-HW-06] 開始時点で提示先があれば、中身の生成の失敗は今までどおり開始の失敗になる
- **GIVEN** 提示先がある状態と、呼ばれると失敗するカスタム View の factory
- **WHEN** Loading を始める
- **THEN** 開始が失敗として呼び出し元へ返り、action は実行されない
