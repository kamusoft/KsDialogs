# Exploration: fix-layout-contract-gaps

## 課題 / 動機

ダイアログの大きさと置き場所を決める core 契約 (`kasane/concepts/core/api/layout-semantics.md`) に、**未規定または記述同士が整合しない箇所が 3 件**ある。いずれも baseline (split-concepts-platform-surface 着手時点) から存在し、同 change の core 書き直し (識別子を platform 側へ移す作業) の中で見つかったもの。契約の穴なので 4 形態 (iOS Native / Android Native / MAUI / KMP) の実装すべてに効く。同 change では「契約の穴は直さない (deviation に記録して蒸留送り)」の裁定で触っていない。

発見の文脈: split-concepts-platform-surface の tasks 2.4 (layout の core 書き直し) と docs-refresh による Skill 再生成 (KMP Skill が SwiftUI 以外の添付競合規則を書けなかった)。

1. **非有限値の一般規則と表の個別規則が ±Infinity で衝突し、適用順が未定** — 一般規則 (`:60` 付近) は「NaN / ±Infinity はその値の既定値として扱う」。表の個別規則は「比率は 0 以下なら未指定、1 超は 1 に丸める」「負の Margin 辺は 0」。+Infinity の比率は一般規則なら既定値・個別規則なら 1 に丸め、-Infinity の Margin 辺は「既定の 24」か「下限の 0」かで結果が割れる。文書は「個別規則は一般規則に加わる具体化」と書くが、どちらを先に適用するかが無い
2. **「いつの値が使われるか」の 3 文が整合しない** (`:81`〜`:86`、`:203`) — 「初回レイアウトパス完了時点の値で決まる」「show を呼んだあとでも、この時点までに書き換えた値は採用され得る」「表示されたときには実効値は確定している」の 3 文があり、show 後・初回レイアウトパス前に添付を書き換えた場合の効果が確定しない (採用される、とも、表示時点で確定済み、とも読める)
3. **中身の View 階層の複数箇所に添付が競合したときの勝敗が SwiftUI 以外で未規定** — SwiftUI は「外側 (親側) が勝つ」と規定済み (`ios/api/layout-surface.md`)。UIKit / Android View / Compose (`KsDialogAttributes`) / MAUI の添付プロパティでは、階層の複数ノードに添付したときどれが読まれるかが書かれていない
