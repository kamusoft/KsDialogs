- 探索「本体 (ToastContainer) には手を入れない」: 維持 (署名で Toast が引き金でないことを確認)
- 指示「今回 CI で落ちたテストを 3 条件の切り分けにかけ、条件を満たすものは `@SkipOnCi` を付ける」: **CI 限定スキップは 1 件も適用していない**。6 件すべてが観測または実行条件の欠陥として直せたため (evidence/ci-flake-triage.md)。LD_CO_13 / LD_WN_01 は手元でも落ちたのでスキップの候補にならず、LD_AT_03 / LD_AT_04 / BV-MA-03 は公開契約の保証そのものを固定する Scenario なのでスキップの対象外。仕組み (Android の `@SkipOnCi` + `SkipOnCiRule`、Swift の trait `.skipOnCi`) は設置し、一時的に 1 件へ印を付けて skip と skipped の計上を確認してから戻した (印はコミットしていない)
- 指示「観測を直す」の適用として、LD_CO_13 の第 1 世代の中身を既定ローディングから「出を一定時間押さえる添付演出を持つカスタム View」へ変えた。端末側でアニメーションを無効にすると既定の出の演出が 0 秒になり、「出の途中」という観測対象そのものが成立しないため。Scenario 名と確かめる内容 (新世代の器・旧世代の撤去・引き継がない) は変えず、メッセージを引き継がない検査の検出力を保つために合流 1 件でメッセージを持たせている
- BV-MA-03 の対応は 2 つ: テストが使う Toast の表示時間を観察の所要から独立させ (60 秒。片付けは期限切れを待たず後始末で器を撤去する。Android 側の同型の解き方に揃えた)、maui job の Swift テストを `-parallel-testing-enabled NO` で回すようにした (ios job と同じ実行条件。並列スイートの飢餓は `kasane/handbook/cross/verification-ci.md` が定める既知の落ち方)。期限を 6.0 秒へ広げる案は、実行機が遅くなれば同じ落ち方が戻るため採らない
- 指示「ios/ と maui/macios/native/ の間で共有できないなら同名の最小実装を両方に」: 両方に置いたが、`ios/` 側は現時点で適用先が無い (ios/ のテストは今回の切り分け対象に入っていない)。仕組みの対称性を優先した
