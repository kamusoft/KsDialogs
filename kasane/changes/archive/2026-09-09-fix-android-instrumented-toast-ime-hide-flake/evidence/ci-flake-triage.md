# CI で落ちたテストの切り分け

反復 CI の 8 run で落ちたテスト ([evidence/ci-repeat-signature.md](ci-repeat-signature.md)「結果 (8 run)」) と、
MAUI iOS 橋渡しの `[BV-MA-03]` を、切り分けフロー (`kasane/handbook/cross/ci-flaky-test-policy.md`) に
かけた記録。手元の反復はすべて下記の条件で行い、実測の前に検証機の負荷を確認した。

## 手元の実行条件

| 項目 | 値 |
|---|---|
| Android | AVD `ksn_api36_headless` (API 36 google_apis arm64)、`-no-window -gpu swiftshader_indirect -noaudio -no-boot-anim -no-snapshot` |
| アニメーション | window / transition / animator の 3 種を 0 (CI の `disable-animations: true` と同条件) |
| 反復の起こし方 | `am instrument -w -e class <クラス#メソッド>` を 10 回 (IME のクラスは 30 回) |
| iOS (MAUI 橋渡し) | この検証のために新規作成した iPhone 17 Simulator (iOS 26.5)、`xcodebuild test -parallel-testing-enabled NO`。終了後に削除 |
| 検証機の負荷 | 実測開始時 load average 3.71 / 3.26 / 3.81 (12 論理 CPU)。居座りの CPU 食いプロセスなし。再実測時も 3.58 / 3.46 / 4.94 で同水準 |

## 切り分けの表

「手元 (対応後)」は下の**版の定義**のどれで測った数字かを併記する。

| テスト | CI での落ち方 | 手元 (対応前) | 診断 | 対応 | 手元 (対応後) |
|---|---|---|---|---|---|
| `ToastSystemInputTests` の IME 出し入れ | 8 run 中 4 回。8 秒の待ちが無音で時間切れ | 旧条件 20 回中 3 回 (同じ署名) | 観測が遷移途中を読む | 終端状態の合意を待つ観測へ (共通プリミティブ) + 最初の要求前の落ち着き待ち | 版 B で 30 回中 0 回 / 版 C で 10 回中 0 回 |
| `LD_CO_13` 出の途中の新しい開始 | 3 回。素の `AssertionError` (10 秒の待ちが時間切れ) | 10 回中 2 回 | 通り過ぎる中間状態をポーリングで捕まえている。アニメーション無効下では「出の途中」が 0 秒に縮む | 出を一定時間押さえる添付演出のカスタム View を第 1 世代にして、途中の窓を作る (合流の成立も前提として固定) | 版 B で 10 回中 0 回 / 版 C で 10 回中 0 回 |
| `LD_WN_01` 画面の変化をまたぐ継続 | 1 回。「前提: 画面の再生成をまたいで器が載せ直されている expected not same」 | 10 回中 1 回 | 再生成の完了を待たずに読んでいる (向きの要求を出した直後は前の器が載ったまま) | 器が載せ直されるまで待ってから読む | 版 B で 10 回中 0 回 / 版 C で 10 回中 0 回 |
| `LD_AT_03` 外側タップで閉じず背後にも透過しない | 1 回。「背後の画面の要素も反応しない expected:<0> but was:<1>」 | 10 回中 0 回 | 器のウィンドウが入力の宛先になる前にタップを注入している | 宛先の切り替わり (取り付け・可視・レイアウト・フォーカスの旗・元のウィンドウの手放し) を待ってから注入する | 版 B で 10 回中 0 回 / 版 C で 10 回中 0 回 |
| `LD_AT_04` ダイアログ表示中の Loading は最前面で入力を遮る | 1 回。「前提: ダイアログの中身はタップを受け取る expected:<1> but was:<0>」 | 10 回中 0 回 | 同上 (ダイアログ側の宛先) | ダイアログ・Loading・閉じた後の 3 点で宛先の切り替わりを待つ | 版 B で 10 回中 0 回 / 版 C で 10 回中 0 回 |
| `[BV-MA-03]` Toast はその 1 枚だけが破棄される | `overlays.added.count == 2` の待ちが時間切れ | 1 回中 0 回 (テスト全体の所要 3.26 秒 / 期限 3.0 秒) | 観察の所要が Toast の期限に追いつかれる。加えて job がスイートを並列で回していた | 表示時間を観察の所要から独立させ (60 秒) 後始末で器を撤去、job の Swift テストを直列で回す | 版 C で 11 回中 0 回 (テスト全体の所要 0.313〜0.323 秒) |

### 版の定義

| 版 | 内容 |
|---|---|
| A | 対応前 (旧条件) |
| B | 硬化 1 段目 + 最初の要求前の落ち着き待ち。BV-MA-03 は期限 6.0 秒 |
| C | B に加えて、宛先の待ちを複数観測の合意 + 履歴付きにし、IME の落ち着きにも独立な観測 (この画面が入力の宛先であること) を足し、LD_CO_13 に合流件数の前提を足し、BV-MA-03 を表示時間の独立化 + 後始末での撤去に置き換えた版 (現行) |

「対応前」の 3.26 秒は**テスト全体の所要**で、期限切れを待つ後始末を含む。観察の窓そのものは版 C の測定 (0.31 秒台) が示すとおり短く、旧構造では後始末が期限に張り付いていた。版 C は片付けを期限から切り離したので、実行機の速さで所要が変わっても枚数と同一性が裏返らない。

## CI 限定スキップの判定

上の 6 件はいずれも**観測または実行条件の欠陥**として直せたため、CI 限定スキップは適用していない。
判定の内訳は次のとおり。

- `LD_CO_13` / `LD_WN_01` は手元でも落ちた (2/10・1/10)。切り分けフローの「手元で落ちるなら直す」に当たり、スキップの候補にならない
- `LD_AT_03` / `LD_AT_04` は手元で通ったが、**入力を遮る・遮らないという公開契約の保証そのもの**を固定する Scenario であり、重要な機能のテストとしてスキップの対象外。観測を直した
- `[BV-MA-03]` も「その 1 枚だけが破棄され、表示中の別の Toast は残る」という公開契約の保証で、同じくスキップの対象外
- IME の出し入れは、この change が原因を特定して硬化した当のテストなので、CI に判定させ続ける

## スキップの仕組みの確認

適用先が無いままでは仕組みが動くことを確かめられないため、一時的に 1 件へ印を付けて確認し、確認後に戻した
(印を付けた状態はコミットしていない)。

| 確認 | 結果 |
|---|---|
| 実行引数 `ksdialogsCi=true` を渡した実行 | 印を付けたテストが `SKIPPED` になる |
| そのときの結果 XML | `tests 6 / skipped 1 / failures 0` — 件数検査が見る「実行数 = tests - skipped」に載る |
| 実行引数を渡さない実行 | 印を付けたテストも通常どおり実行される (6 件すべて実行) |

## 全件の実測 (版 C)

| ルート | 件数 |
|---|---|
| android instrumented (`connectedDebugAndroidTest`) | `:ksdialogs-core` 294 件 (skipped 1・失敗 0) / `:ksdialogs` 39 件 (skipped 0・失敗 0) |
| android JVM (`test --rerun-tasks`) | 68 件 / 失敗 0 |
| maui/macios/native (`xcodebuild test`) | 7 tests / 4 suites・失敗 0 (11 回反復して全て成功) |
