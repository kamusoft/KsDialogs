# Deviation: fix-android-startup-toast-under-splash

- CA-SA-10 / tasks 1.2・7.1: spec では Toast の 2 デモを 3 ルートとも「コールド起動とプロセスが残ったままの再起動のどちらでも」5 回撮る → 指示により、プロセスが残ったままの再起動は android ルートだけで撮り、kmp・MAUI はコールド起動だけで撮る。理由: kmp・MAUI の Sample は、デモの指定が無い起動でも自動再生の取り出しを使い切る作りで、Sample を変えずにこの場面を作れない。この場面の提示先の振る舞いは android ルートで押さえられ、kmp・MAUI の Android の提示先の判定は Native に任せている (2026-09-29)
- tasks 1.3・7.2 (前面の待ちの間に受け付けた Toast は、提示先に載った時点から計時する — iOS の割り込みの場面): tasks では「Sample に手を入れずに場面を作れなければ止めて報告する」 → 指示により、許可ダイアログを出す一時的な変更を iOS 系 Sample に入れて撮り、撮った後に元に戻してチェックサムで元と一致することを確かめる。一時的な変更は成果物に残さない。理由: iOS 系 3 ルートの Sample は許可ダイアログを出す処理を持たず、前回 (wait-for-host-appearance) と同じ手順が handbook と実績でそろっている (2026-09-29)
- design Decision 7 / CA-SA-10 / tasks 7.4 (合格ラインの測り方): design では「起動画面が退いたコマ (Toast が見え始めたコマ) から Toast が消えたコマまで」 → 指示により、起点は起動画面の退場のフェードが終わり切ったコマ (それより後に Toast が見え始めたときはそのコマ) とする。フェードの途中で見えている時間は数えない。理由: 「退いた後に見えている」の字義に最も近く、直す前の実測と同じ定義で比べられる (2026-09-29)
- [付随修正] androidTest `support/FirstDrawBlockingTestActivity.kt` (グループ 2 で追加した試験用 Activity): 構成の変更による作り直しではウィンドウが引き継がれ、旧画面が張った「描画しない」listener が残って新しい画面が描画されなかった → `onDestroy` で自分の listener を外し、作り直して新しい画面を待つ `recreateAndWait()` を足した。担保: PB-HA-04・PB-HA-11 の instrumented テストの成功 (2026-09-29)
- [付随修正] iOS `ios/Sources/KsDialogs/Presentation/KsToast.swift` の公開 doc コメント: 「表示は受理された時点から数える」だけでは新しい時間モデルと合わない → 前面にいるのに表示先の画面が無い間に受け付けた表示は、画面に表示された時点 (その前に背面へ移ったときはその時点) から数える旨を足した。公開 API の形は変えていない。担保: TS-HW-04〜06 (2026-09-30)
- [付随修正] Android `android/ksdialogs-core/src/main/kotlin/jp/kamusoft/ksdialogs/KsToast.kt`・KMP `kmp/ksdialogs-kmp/src/commonMain/kotlin/jp/kamusoft/ksdialogs/kmp/KsToast.kt`・MAUI `maui/KsDialogs.Maui/Presentation/IKsToast.cs` の公開 doc コメント: iOS の `KsToast.swift` と同じく、前面にいるのに表示先の画面がまだ無い間に受け付けた表示は、画面に表示された時点 (その前に背面へ移ったときはその時点) から数える旨を足した。シグネチャは変えていない。担保: TS-HW-04〜06 (Android / iOS) と各形態のビルド・テスト (2026-09-30)
- design Decision 1 (「Loading・Toast の載せ直しには手を入れない」) / tasks 7: design では印を立てたときの通知で Loading・Toast の載せ直しがこれまでどおり動くとしていたが、stop で描画の印を下ろすため、背面から戻るたびに載っている器が外れ、戻った画面の最初の描画の後に演出なしで載り直す (review-001 Major) → 指示により、Loading・Toast の `onHostChanged` で、新しい提示先が無く、載っている Activity がまだ破棄されていないときは器を外さない。外すのは、載っている Activity が破棄されたときか、描画済みの別の提示先が現れたときに限る。あわせて tasks 7 の実測に「Loading の表示中に背面へ下がって戻る」場面 (戻った後の最初の描画のコマに Loading が写っているかを録画で見る) を足す。理由: 直す前の Android と iOS の振る舞い (背面の間も器を付けたまま) を保つ。core/ADR-0044 の狙いは見えていない画面に新しく載せないことで、付いている器を外すことまでは求めない (2026-09-30)
- design Decision 1 (描画の取りこぼしの保険): design では「resume の時点で印が立っていなければ decorView の `invalidate()` で描画を促す」だけ → review-001 の Major (レビュー双方一致) により、次の 2 つを足した。(a) 未描画のまま resume した時点で描画の観測が始まっていなければ (decorView が無く観測を始められていない)、観測を張り直してから描画を促す。(b) start の次の周回で decorView を取り直して観測を張ったときも、その場で描画を促す (取り直す前に最初の描画が済んでいても、後続の描画を偶然待たない)。判断そのもの (提示先は resumed で、かつ描画された Activity) は変えていない (2026-09-30)
- 上の B の実装の形 (2026-09-30 の項を補う): 「載っている Activity がまだ破棄されていない」は、提示先と同じ追跡役が受けた破棄の通知の記録と `Activity.isDestroyed` で判定する (finishing 中で未破棄の画面には器を残す)。Loading・Toast の提示面の口に「載っている画面の器を残せるか」の問い合わせを足し、`onHostChanged` はそれを使って外すかどうかを決める。Toast の未確定の期限を前面を離れた通知で決める処理は、この判定より前にそのまま行う (2026-09-30)
- [付随修正ではなく review-001 Minor への対応] Android `KsDialog.show` の公開 doc: 提示先の説明を「前面で表示されている画面」とし、前面にあってもまだ一度も表示されていない画面 (起動画面の下で開いている途中の画面など) は提示先にならない旨を足した。シグネチャは変えていない (2026-09-30)
- design Decision 7 / tasks 7.1・7.4 (直した後の実測の手順): design では直す前と同じ端末・同じ手順で撮る → 1 回目の直した後の実測で、負荷の高さ (load average 9〜16、他のセッションのエミュレータが同時に稼働) により録画の途切れ・コマの欠けが起き、合格ラインを割った回が測り方の誤差か実際の先走りか切り分けられなかったため、指示により次のとおり撮り直す。(a) 撮る前に負荷と他のエミュレータの稼働を確かめ、負荷の低い状態で撮る。(b) 録画の解像度とビットレートを下げてコマの欠けを減らす。(c) ライブラリに取り付けの時刻を出す一時的な診断出力を入れ、録画のコマと突き合わせる。一時変更は撮った後に元に戻し、チェックサムの一致と git diff が空であることを確かめる。合格ラインの判定は撮り直した結果で行い、1 回目の結果は evidence に参考として残す。撮り直しても割ったら止めて諮る (2026-09-30)
- design Decision 7 / tasks 7.1・7.4 (直した後の実測の端末): design では Android エミュレータ (API 36) で撮る → エミュレータでの撮り直しでも合格ラインを割り (custom-toast で取り付けから見え始めるまで 0.47〜2.69 秒遅れる回があり、load average は最大 29)、環境の負荷とライブラリの振る舞いを切り分けられなかったため、指示により接続中の実機 Pixel 6a (API 36) で撮る。合格ラインの判定は実機の結果で行い、エミュレータの 2 回分は参考として残す。録画の設定と一時的な診断出力は撮り直しと同じ。まず android ルートの Toast 2 デモを撮り、遅れが消えれば残りの場面も実機で撮り、遅れが残れば止めて諮る。直す前の実測はエミュレータのままとする (2026-09-30)
- design Decision 7 / tasks 7.4 (合格ラインの測り方の補い): 起動画面が退いたコマの判定 (以降もずっと基準のコマと一致したままの最初のコマ) は、実機の MAUI の custom-toast の録画で、Toast が消えた直後の 2〜3 コマ (約 0.03 秒) だけ画素の差が閾値をわずかに超える色の揺れを拾い、退いたコマが撤去の後までずれた (目視では 2 枚とも見えている) → 指示により、判定に「一致するコマに挟まれた 3 コマ以下の不一致は無視する」を足す。ほかの回の値は変わらない。起点をフェードが終わり切ったコマとする定義 (上の項) は変えない (2026-09-30)
- CA-SA-10 (実機の撮影の 1 回の差し替え): android ルートの default-toast のコールド起動の 1 回目は、起動直後に端末で最近のアプリの画面が開いて Sample が背面へ下がった (撮影の操作ではない) ため、Scenario の WHEN (起動直後から連続で撮影する) を満たさない回として無効にし、6 回目で代えた。差し替えたのはこの 1 回だけ (2026-09-30)
