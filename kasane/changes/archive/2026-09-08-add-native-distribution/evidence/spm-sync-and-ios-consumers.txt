## 4. ios/ の全テスト (iOS Simulator destination)

`ios/` は本作業で無改変:

    $ git diff --stat ios/
    (出力なし)
    $ git status --porcelain ios/
    (出力なし)

Simulator は起動中のものを流用せず、専用に新規作成した機体 (iPhone 17 Pro / iOS 26.5) を
boot して使用した。

コマンド: cd ios && xcodebuild test -scheme KsDialogs \
    -destination 'platform=iOS Simulator,id=<UDID>' -parallel-testing-enabled NO

    ✔ Test run with 277 tests in 50 suites passed after 88.494 seconds.
    ** TEST SUCCEEDED **

277 件 (1 件以上) が成功。50 スイートすべてが ✔。

補足 (並列既定での先行実行): 同じ機体・同じコマンドから -parallel-testing-enabled を
外した実行では 277 件中 5 件が失敗した。失敗はいずれも提示待ちの時間切れ
([MB-TS-01] / [PB-KC-03] / [TS-CO-01] / [TS-IO-02] / [TS-TR-01]) で、待ちの上限 5 秒に対して
9.8〜14.6 秒後に落ち、Toast / ModelBinding / KMP トランジションと無関係な領域に散っている。
これは検証 CI の ios job を直列で回す理由として handbook が記す並列スイートの飢餓の形と
一致する (実行機の容量差であってテスト・実装の欠陥ではない)。直列実行で全件が通ることを
上記のとおり確認した。

## 5. iOS 消費者のビルド (Local Swift Package 参照のまま)

### samples/ios

コマンド: cd samples/ios && xcodebuild -project KsDialogsSample.xcodeproj \
    -scheme KsDialogsSample -destination 'platform=iOS Simulator,id=<UDID>' \
    -derivedDataPath DerivedData CODE_SIGNING_ALLOWED=NO build

    ** BUILD SUCCEEDED **

ログには `in target 'KsDialogs' from project 'KsDialogs'` として `ios/Sources/KsDialogs/` 配下の
`.swift` をコンパイルする行が並び、ローカルの `ios/` を Swift Package として解決していることが
読み取れる (例: `/ios/Sources/KsDialogs/Registry/LoadingViewRegistry.swift`)。

### maui/macios/native (iOS binding の Swift 橋渡し)

コマンド: cd maui/macios/native && xcodebuild -project KsDialogsMauiBridge.xcodeproj \
    -scheme KsDialogsMauiBridge -destination 'platform=iOS Simulator,id=<UDID>' \
    -derivedDataPath DerivedData CODE_SIGNING_ALLOWED=NO build

    ** BUILD SUCCEEDED **

同じく `in target 'KsDialogs' from project 'KsDialogs'` で `ios/Sources/KsDialogs/` を
コンパイルしており、Local Swift Package 参照のまま `KsDialogsMauiBridge.framework` が
生成される。
