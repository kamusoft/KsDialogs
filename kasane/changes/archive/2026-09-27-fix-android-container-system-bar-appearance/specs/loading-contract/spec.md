# loading-contract デルタ (fix-android-container-system-bar-appearance)

Scenario ID は `LD-SB-<NN>` (Loading の器とシステムバー) を新設する。挙動は Native 2 実装 (iOS / Android) の同名テストで全量を検証する (core/ADR-0016)。LD-SB 領域は網羅検査の両 Native ミラー対象 (`scripts/scenario-id-coverage.py` の `MIRROR_AREAS`) に足す。決定の出典は core/ADR-0039。既存の Loading 契約 (器の性質・合流・進捗・失敗・終了の時点) は変えない — 本書はシステムバーの指定の非干渉の追加分のみ。

明暗の Scenario が判定するのは、**ステータスバーの明暗を決める指定**であって、実際に描かれた文字色ではない (暗幕に合わせて OS が文字色を選ぶことは要件の外のため)。各 Native の観測のしかた:
- Android: 器のウィンドウの指定 (明暗・可視状態・再表示の作法) が、テストが提示先に与えた指定と同じであること。比べる相手は、テストが与えた指定から組み立てた期待値であり、提示先のウィンドウから OS が返す値ではない (android-native デルタ)。可視状態は、器の要求に加えて、画面上のバーが実際に隠れたままであることも見る
- iOS: UIKit がステータスバーの見えを尋ねる相手が提示先のままであること。Loading の器は key window に View を重ねるだけで (`ios/Sources/KsDialogs/Presentation/LoadingPresentationSurface.swift` の `KeyWindowLoadingPresentationSurface`)、画面 (view controller) の提示も、画面の親子関係への組み込みもしない。表示中も key window の root が提示先のままで、提示先に提示中の画面が増えていないことを確かめる。器が画面を提示する・親子関係に組み込む退行はこの観測で検出できる

## ADDED Requirements

### Requirement: システムバーの指定の非干渉 (Loading)

Loading の器は、表示中も提示先の画面のシステムバーの指定を変えない (SHALL)。変えない指定は、ステータスバーのアイコンの明暗、バーの表示/非表示、隠れたバーの再表示の作法 (その概念を持つ OS のみ) である。

暗幕 (覆い) がステータスバーの下を暗くしたときに、OS がそれに合わせてステータスバーの文字色を選ぶことは、この要件の外に置く。器は指定を変えておらず、見えの変化は OS の判断による。

この要件が定めるのは、表示を始めた時点の提示先の指定を変えないことである。表示中に提示先が指定を変えた場合の扱いは、この要件では定めない。

#### Scenario: [LD-SB-01] 明るい地向けの明暗を指定した画面で Loading を出しても、明暗の指定は変わらない
- **GIVEN** 提示先の画面が、ステータスバーのアイコンを明るい地向け (暗い色) に指定している
- **WHEN** 既定ローディングを表示する
- **THEN** 表示中も、ステータスバーの明暗を決める指定は提示先の画面のもの (明るい地向け) のままで、器の指定に置き換わらない

#### Scenario: [LD-SB-02] バーを隠した画面で Loading を出しても、バーは隠れたまま
- **GIVEN** 提示先の画面が、ステータスバーを隠している (ナビゲーションバーを持つ OS では、ナビゲーションバーも隠している)
- **WHEN** 既定ローディングを表示する
- **THEN** 表示中もバーは隠れたままである。隠れたバーの再表示の作法を持つ OS では、器の作法も提示先と同じである
