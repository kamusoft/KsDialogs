# android-native デルタ (fix-android-container-system-bar-appearance)

core 契約の挙動 Scenario (dialog-contract の PB-SB-08、loading-contract の LD-SB-*、toast-contract の TS-SB-*) は同名の instrumented テストで検証する (core/ADR-0016)。本書は Android に固有の差分 — 引き継ぐ指定の範囲、器の種類、指定の読み取り、透明な覆いの見え — だけを書く。決定の出典は core/ADR-0039。

実現経路: Dialog の器は、decorView が画面に載った時点で `DialogWindowSystemBars.inheritSystemBarState` を 1 回呼び、提示先の Activity のウィンドウから指定を写している (`android/ksdialogs-core/src/main/kotlin/jp/kamusoft/ksdialogs/DialogContainer.kt:101`・`DialogWindowSystemBars.kt:72`)。Loading / Toast の器 (`LoadingContainer.kt:90`・`ToastContainer.kt:85` の `onCreate`) は `makeSystemBarBackgroundsTransparent` だけを呼んでおり、写していない。3 つの器はどれも提示先の Activity を context にして作られる (`LoadingCoordinator.kt:384`・`ToastCoordinator.kt:173`)。画面の作り直しで器を載せ替える経路 (`detachForReattach`) では新しい器が作られるので、載った時点で写す形なら載せ替え先の画面から写すことになる。透明な覆いの見え (PB-SB-11) は、器のウィンドウがシステムバーの背景を自分で描く既存の作り (`DialogWindowSystemBars.makeSystemBarBackgroundsTransparent`) が支えている。

テストの比べ方: 器の指定は、**テストが提示先に与えた指定から組み立てた期待値**と比べる。提示先のウィンドウから OS が返す値とは比べない — 旧来のフラグだけで明暗を指定した提示先では OS が 0 を返し、作法を指定していない提示先では OS が 0 を返すため、正しく引き継いだ器の値と食い違う。作法を指定していない場合の期待値は、作法を指定していないウィンドウの OS の既定値とする。

## MODIFIED Requirements

### Requirement: システムバー表示状態の引き継ぎ

Dialog / Loading / Toast の器のウィンドウは、画面に載った時点で、提示先の画面のシステムバーの指定を引き継ぐ (SHALL)。

- API 30 以上では、ステータスバー / ナビゲーションバーそれぞれの可視状態、隠れたバーの再表示の作法 (systemBarsBehavior)、アイコンの明暗 (明るい地向けのステータスバー / ナビゲーションバー) を引き継ぐ
- API 24〜29 では、systemUiVisibility の丸ごとのコピーにより、可視状態と明暗を引き継ぐ

引き継ぎは表示時の 1 回で、表示中の提示先の状態変化には追随しない。

提示先の指定のしかたによらず引き継ぐ。
- 明暗: 提示先が明暗を旧来のフラグ (systemUiVisibility の明るいステータスバー / ナビゲーションバーのフラグ) だけで指定している場合も、その指定を引き継ぐ
- 再表示の作法: 提示先が作法を指定していない場合、器の作法は、作法を指定していないウィンドウの OS の既定と同じになる

Toast の器はフォーカスを取らないため、バーの表示/非表示の制御は提示先に残る。器が可視状態を引き継いでも、提示先のバーの状態は変わらない。

#### Scenario: [PB-SB-01] 全システムバー非表示の画面でダイアログを出してもバーが再出現しない (API 30+)
- **GIVEN** API 30 以上で提示先の画面が status / navigation 両方を非表示にしている
- **WHEN** ダイアログを表示する
- **THEN** 両バーは非表示のまま維持され、systemBarsBehavior も提示先と同じになる

#### Scenario: [PB-SB-02] ステータスバーのみ非表示の画面を引き継ぐ (API 30+)
- **GIVEN** API 30 以上で提示先の画面が status のみ非表示にしている
- **WHEN** ダイアログを表示する
- **THEN** status は非表示のまま、navigation は表示のまま維持される

#### Scenario: [PB-SB-03] ナビゲーションバーのみ非表示の画面を引き継ぐ (API 30+)
- **GIVEN** API 30 以上で提示先の画面が navigation のみ非表示にしている
- **WHEN** ダイアログを表示する
- **THEN** navigation は非表示のまま、status は表示のまま維持される

#### Scenario: [PB-SB-04] 旧経路 (API 24〜29) でも非表示状態が維持される
- **GIVEN** API 24〜29 で提示先の画面が immersive フラグでシステムバーを非表示にしている
- **WHEN** ダイアログを表示する
- **THEN** システムバーは非表示のまま維持される

#### Scenario: [PB-SB-05] 通常表示の画面では従来どおり
- **GIVEN** 提示先の画面がシステムバーを表示している
- **WHEN** ダイアログを表示する
- **THEN** システムバーの表示状態は変化しない

#### Scenario: [PB-SB-06] 表示後の提示先の可視状態の変更には追随しない
- **GIVEN** API 30 以上で提示先の画面がシステムバーを表示した状態でダイアログを表示中
- **WHEN** 提示先の画面がシステムバーを非表示に変更する
- **THEN** ダイアログのウィンドウの可視状態は表示時に採用した値 (表示) のまま変わらない

#### Scenario: [PB-SB-07] 表示後の提示先の behavior の変更には追随しない
- **GIVEN** API 30 以上で提示先の画面が既定の systemBarsBehavior でダイアログを表示中
- **WHEN** 提示先の画面が systemBarsBehavior を変更する
- **THEN** ダイアログのウィンドウの behavior は表示時に採用した値のまま変わらない

#### Scenario: [PB-SB-09] 旧来のフラグだけで明暗を指定した画面でも、ダイアログは明暗を引き継ぐ (API 30+)
- **GIVEN** API 30 以上で、提示先の画面が systemUiVisibility の明るいステータスバーのフラグと明るいナビゲーションバーのフラグだけで明暗を指定している (WindowInsetsController では指定していない)
- **WHEN** ダイアログを表示する
- **THEN** ダイアログのウィンドウのステータスバーとナビゲーションバーの明暗は、それぞれ明るい地向けになる

#### Scenario: [PB-SB-10] 作法を指定していない画面では、ダイアログの作法は OS の既定になる (API 30+)
- **GIVEN** API 30 以上で、提示先の画面が隠れたバーの再表示の作法を指定していない
- **WHEN** ダイアログを表示する
- **THEN** ダイアログのウィンドウの作法は、作法を指定していないウィンドウの OS の既定と同じになる

## ADDED Requirements

### Requirement: 透明な覆いでステータスバーが暗くならない

覆いの色に透明を指定した Dialog の表示中、ステータスバーの帯の見えは表示前と変わらない (SHALL)。OS が器のウィンドウのステータスバーの下に既定の暗い覆いを敷かないことを、実際の見えで確かめる要件である。

この検査は画面の明るさを測るので、比べる前に次の状態をそろえる。
- 提示先がステータスバーのアイコンを明るい地向けに指定している (白地に白いアイコンのように、差が出ない状態で比べない)
- 起動時の表示 (スプラッシュ) が画面から外れ、ステータスバーの見えが提示先自身のものになってから「表示前」を測る

「提示先自身の見えになった」は、明るさの安定だけで判定しない (止まって見えるスプラッシュを落ち着いた提示先と読み違えるため)。明るさとは独立の観測で、提示先のウィンドウがフォーカスを持ち、提示先自身の描画が画面に出て、起動時の表示のウィンドウが無くなったことを確かめる。この終端条件が時間内に成り立たなければ、測定せずにテストを失敗させる (成り立たないまま測って比べない)。

#### Scenario: [PB-SB-11] 透明な覆いのダイアログを出しても、ステータスバーの帯の明るさは変わらない
- **GIVEN** 明るい地の提示先の画面が、ステータスバーのアイコンを明るい地向けに指定しており、起動時の表示が画面から外れたこと (上記の終端条件) を確かめてある
- **WHEN** 覆いの色に透明を指定したダイアログを表示する
- **THEN** 表示中のステータスバーの帯の明るさは、表示前と変わらない (許容差の範囲内)
