# レビュー指摘の修正 4: README 一致 lint の節重複の抜け道 (2026-09-09)

判定: **成立** (文書全体の見出し数を fence 内外を区別して数え、1 件以外を失敗にした。
自己テストの新しい負ケースは、この検査を外すと落ちる)

## 変更

scripts/readme-example-lint.py に count_section_headings() を足し、lint() の先頭で
「## Minimal examples」の見出し数がちょうど 1 件であることを確かめる。fence の開始・終了で
状態を反転させ、コードブロック内の見出し風の行は数えない。

自己テストに 3 つの検査を追加した。
  - 最小例の節の見出しを 1 件だけ数える
  - fence の中の見出し風の行は数えない
  - 節が 2 つある README で exit 1 になり、節の個数が出力される

## 自己テストと本検査

  $ python3 scripts/readme-example-lint.py --selftest
  [抽出ロジック]
    OK   最小例の節のブロックだけを取る (実際 4 件)
    OK   Installation 節の同名見出しを拾わない
    OK   最小例の節の見出しを 1 件だけ数える (実際 1 件)
    OK   fence の中の見出し風の行は数えない (実際 1 件)
    OK   対応表の 4 件すべてが解決する
    OK   同じ fence 言語の 2 件は小見出しで振り分ける
  [検査の疎通]
    OK   一致していれば exit 0
    OK   片側だけの変更で exit 1
    OK   不一致のファイルが出力される
    OK   一致しているファイルは報告しない
    OK   同じ見出し・言語の重複で exit 1
    OK   重複した候補数が出力される
    OK   最小例の節が 2 つあれば exit 1
    OK   節の個数が出力される
        (エラー: README.md の ## Minimal examples 節が 2 個ある (1 個だけであるべき))
    OK   対応先が無ければ exit 1
    OK   不在の理由が出力される
  失敗なし   exit=0

  $ python3 scripts/readme-example-lint.py
  README の最小例 4 件が消費者検証のソースと一致する   exit=0

## 新しい負ケースが本当に新設の検査を通っていること

見出し数の判定だけを無効にした写しをスクラッチに作り、同じ自己テストを回した。

  $ python3 <見出し数の判定を無効にした写し> --selftest
    NG   最小例の節が 2 つあれば exit 1
    NG   節の個数が出力される (README の最小例 4 件が消費者検証のソースと一致する)
  失敗 2 件

節が 2 つある README は、判定が無いと 1 つ目の節だけを見て成功していた (見せかけの負ケース
ではない)。他の 12 項目は写しでも OK のままで、既存の検査には影響していない。
