## 観測 4: linkage package を再生成するのは link タスクではない (design と相違)

`linkReleaseFrameworkIosSimulatorArm64` の実行では linkage package は生成も更新も
されない。生成されるのは環境変数 `XCODEPROJ_PATH` を与えたときの
`generateSyntheticLinkageSwiftPMImportProjectForLinkageForCli`
(`integrateLinkagePackage` が依存する) である。

$ ./gradlew :shared:linkReleaseFrameworkIosSimulatorArm64      # XCODEPROJ_PATH なし
  -> KotlinMultiplatformLinkedPackage は 1 つも生成されない

$ XCODEPROJ_PATH=<consumer>/iosApp/VerificationKmp.xcodeproj \
    ./gradlew :shared:integrateLinkagePackage
> Task :shared:generateSyntheticLinkageSwiftPMImportProjectForLinkageForCli
> Task :shared:integrateLinkagePackage FAILED
  (合成 package は `<consumer>/iosApp/KotlinMultiplatformLinkedPackage/` に生成された。
   FAILED は xcodeproj の実体がまだ無く plutil が pbxproj を読めないため。
   実在する xcodeproj を置く 2.5 では起きない)

Swift 参照は subpackage 側の manifest が持つ。
`KotlinMultiplatformLinkedPackage/subpackages/jp_kamusoft_ksdialogs_kmp_0_0_0_alpha_0/Package.swift`:

  .package(
    url: "file://<scratch>/premise/KsDialogs-SPM",
    exact: "0.0.0-alpha.0"
  )
  .product(name: "KsDialogs", package: "KsDialogs-SPM")

ルートの `KotlinMultiplatformLinkedPackage/Package.swift` は subpackage を
`.package(path: "subpackages/...")` で参照するだけで、URL を持たない。
subpackage のディレクトリ名は座標と version から作られる
(`jp_kamusoft_ksdialogs_kmp_0_0_0_alpha_0`)。

再生成の効き目 (URL を書き戻すか) を、smoke 形に書き換えてから確かめた:

  a. subpackage の URL を `https://github.com/kamusoft/KsDialogs-SPM` に手で書き換え
  b. `./gradlew :shared:linkReleaseFrameworkIosSimulatorArm64`
     -> URL は https のまま (UP-TO-DATE)
  c. `./gradlew --rerun-tasks :shared:linkReleaseFrameworkIosSimulatorArm64`
     -> URL は https のまま (実行された task は link 系 3 つのみ)
  d. `XCODEPROJ_PATH=... ./gradlew
      :shared:generateSyntheticLinkageSwiftPMImportProjectForLinkageForCli`
     -> URL が `file://<scratch>/premise/KsDialogs-SPM` に戻る

したがって「作業コピーで再生成してから消費者ビルドを行う」という design Decision 4 の
組み立て自体は成立するが、その 2 段目に置くタスクは link タスクではなく
`integrateLinkagePackage` (実在する xcodeproj が要る) または
`generateSyntheticLinkageSwiftPMImportProjectForLinkageForCli` で、いずれも
`XCODEPROJ_PATH` の指定が要る。
