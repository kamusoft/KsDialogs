wait-published の複数 ID 対応と上限の自己テスト (実行日 2026-09-10)

すべて手元で実行。--selftest は HTTP 送信関数をモックへ差し替えるため、ネットワークにも
実レジストリにも出ない。判定行だけを残した抜粋 (括弧内の詳細は長いので落とした)。

### 1. scripts/release/central-portal.sh --selftest  (exit 0、OK 60 件 / NG 0 件)

新規に足した検査 (抜粋):

[wait-published]
  OK   検証待ちの上限は公開待ちに効かない
[wait-published の複数 ID]
  OK   2 件が別々のタイミングで PUBLISHED になれば成功する
  OK   1 ループで全枠を照会する (直列なら 2 件目も aaa になる)
  OK   公開済みの枠は次のループで照会しない
  OK   残った枠だけを照会し続ける
  OK   2 件のうち 1 件が FAILED なら失敗する
  OK   FAILED を見つけた時点で止まる
  OK   2 件とも未公開のまま上限を過ぎれば失敗する

複数 ID の台本は PUBLISHING, PUBLISHING, PUBLISHED, PUBLISHING, PUBLISHED で、
照会順は aaa, bbb, aaa, bbb, bbb になる。並行と直列を分ける観測点は 2 件目の照会
(直列に待ち切る実装なら 2 件目も aaa)。照会の総数 (5 件) と最後の ID (bbb) は
直列実装でも一致するため、件数や末尾だけでは両者を分けられない。

前と同じ挙動)。

### 3. 逆対照 B: 直列版 (ID ごとに公開まで待ち切る写し) で同じ自己テストを回す  (NG 1 件)

cmd_wait_published を `for id in "$@"; do while :; do ... done; done` の形へ
差し替えた写し。並行待ちを外しても複数 ID は扱えるため、分かれるのは観測点を
2 件目の照会に置いた 1 件だけになる。

[wait-published の複数 ID]
  OK   2 件が別々のタイミングで PUBLISHED になれば成功する
  NG   1 ループで全枠を照会する (直列なら 2 件目も aaa になる)
  OK   公開済みの枠は次のループで照会しない
  OK   残った枠だけを照会し続ける
  OK   2 件のうち 1 件が FAILED なら失敗する
  OK   FAILED を見つけた時点で止まる
  OK   2 件とも未公開のまま上限を過ぎれば失敗する

(「公開済みを外さず毎ループ全件を照会する」写しも作って回したが、この台本を
 使い切っても待機対象が減らないため終わらない。上限の既定 5400 秒まで回り続けるので
 判定行が出ず、対照として並べられない。この実装が検査群を通らないことは同じ)

### 4. 逆対照 C: 上限の変数を分けていない版で同じ自己テストを回す  (NG 1 件)

公開待ちの上限を検証待ちと同じ `KSR_POLL_TIMEOUT_SECONDS` (既定 1800) から取り、
自己テスト側の上限指定も同じ変数に戻した写し。公開待ち専用の変数
`KSR_PUBLISHED_TIMEOUT_SECONDS` (既定 5400) を持つかどうかで分かれる。

[wait-published]
  OK   上限を過ぎれば失敗する
  NG   検証待ちの上限は公開待ちに効かない
