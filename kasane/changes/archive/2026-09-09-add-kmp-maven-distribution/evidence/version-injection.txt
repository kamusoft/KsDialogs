# KMP の version の単一ソースと注入の確認 (2026-09-09)

実行場所: kmp/ (Gradle 9.7.0 / AGP 9.3.0 / Kotlin 2.4.10)
導出式: kmp/build.gradle.kts の `providers.gradleProperty("version").orNull ?: カタログの ksdialogs`
カタログ既定値: android/gradle/libs.versions.toml の `ksdialogs = "0.1.0-SNAPSHOT"`
発行先: ケースごとの空の一時 Maven local repository (`-Dmaven.repo.local=<scratch>/case-N`)。
        実行前に対象ディレクトリのファイル数が 0 であることを確認している。

## 1. 注入なしの開発既定値 (case-1)

$ ./gradlew publishToMavenLocal -Dmaven.repo.local=<scratch>/case-1
BUILD SUCCESSFUL in 2s

発行された 5 publication (`<scratch>/case-1/jp/kamusoft/` 配下):

  ksdialogs-kmp/0.1.0-SNAPSHOT/
  ksdialogs-kmp-android/0.1.0-SNAPSHOT/
  ksdialogs-kmp-iosarm64/0.1.0-SNAPSHOT/
  ksdialogs-kmp-iossimulatorarm64/0.1.0-SNAPSHOT/
  ksdialogs-kmp-iosx64/0.1.0-SNAPSHOT/

android publication の POM (`ksdialogs-kmp-android-0.1.0-SNAPSHOT.pom`) が記す本体依存:

      <groupId>jp.kamusoft</groupId>
      <artifactId>ksdialogs-core</artifactId>
      <version>0.1.0-SNAPSHOT</version>
      <scope>compile</scope>

→ artifact の version と本体依存の version がともにカタログ既定値になる。

## 2. リリース version の注入

`-Pversion=0.1.0-beta.1` を渡した発行物の version と依存版は
evidence/publish-to-maven-local.txt と evidence/android-version-alignment.txt が持つ
(いずれも 5 publication すべてが `0.1.0-beta.1`、android publication の POM の
`ksdialogs-core` 依存も `0.1.0-beta.1`)。

## 3. 不正な注入値の拒否

`./gradlew help -Pversion=<値>` を値ごとに実行した結果:

| -Pversion の値 | 結果 |
|---|---|
| (空文字) | BUILD FAILED |
| ` 1.0.0 ` (前後に空白) | BUILD FAILED |
| `v1.0.0` | BUILD FAILED |
| `1.0.0-pre` | BUILD FAILED |
| `0.1.0-beta.1` | BUILD SUCCESSFUL |

失敗時のメッセージ (値の部分だけが変わる。下は空文字と空白入りの 2 例):

* What went wrong:
-Pversion に指定できるのは X.Y.Z または X.Y.Z-{alpha|beta|rc}.N の形式だけです (指定値: "")。注入しなければ開発用の既定値が使われます。

* What went wrong:
-Pversion に指定できるのは X.Y.Z または X.Y.Z-{alpha|beta|rc}.N の形式だけです (指定値: " 1.0.0 ")。注入しなければ開発用の既定値が使われます。

4 件とも `help` タスクに到達する前 (ビルド設定の段階) で失敗し、android/ 側と同じ文言が出る。
空文字が「注入あり」と解釈されて SNAPSHOT ガードを迂回する経路はここで塞がれている。
