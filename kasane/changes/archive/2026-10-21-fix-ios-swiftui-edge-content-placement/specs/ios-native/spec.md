# ios-native デルタ (fix-ios-swiftui-edge-content-placement)

iOS の器 (Dialog・Loading・Toast) に載せた中身について、2 つの差分を扱う。1 つは、窓全体基準で端に付けた SwiftUI の中身が安全領域の内側に収まらないときの並び方。もう 1 つは、大きさを中身に委ねた軸が、上限の拡大に追従すること。Scenario ID は前の change (`deliver-swiftui-content-safe-area-ios`) から続く `PB-IS-<NN>` を使う。3 機能は同じホストを通るため、Dialog で全条件を、Loading・Toast で代表の条件を固定する。

用語:
- 重なり: 中身の矩形 (窓の座標) と、窓の安全領域の外側 (システムの領域) が重なる幅。辺ごとに測る
- 端の軸: レイアウトの解で、その軸の位置が前端 (左 / 上) か後端 (右 / 下) に固定される軸。配置 start / end と、比率サイズを伴わない fill がこれに当たる。中央の軸: 位置が中央に固定される軸 (配置 center と、比率サイズを伴う fill)
- 片側の端の軸: 端の軸のうち、配置 start / end の軸。比率サイズの有無を問わない (fill は両側の端の軸)
- 大きさを中身に委ねた軸: 比率サイズも fill も指定しない軸。その軸の大きさは要求サイズで決まり、有効領域 (基準領域から余白を除いた領域) の大きさで頭打ちになる
- 要求サイズ: 器へ伝える中身の大きさ。制約を付けずに求めた中身の理想の大きさ。器が有効領域で頭打ちにした軸があれば、置かれた幅で折り返した大きさ
- 中身が受け取る安全領域: SwiftUI の中身の一番外側の View から見える、SwiftUI 標準の安全領域
- 安全領域の内側: 器の矩形から、中身が受け取る安全領域を除いた領域
- 縮まない中身: 理想の大きさより小さくならない SwiftUI の中身 (固定サイズの指定、または縮められない部品を並べたもの)。縮められる中身: 提案された大きさまで縮む中身
- 内側の辺: 片側の端の軸で、器が付いた側と反対の辺 (上端に付けたら下の辺、下端なら上の辺、左端なら右の辺、右端なら左の辺)。左右は物理の向きで決め、書字方向に左右されない
- 描かれた位置: 中身が実際に描画される矩形 (窓の座標)

共通の試験条件 (Scenario に書いていなければこれを使う):
- 縦長の窓: 393 × 852、安全領域は上 59・下 34・左右 0。横長の窓: 852 × 393、安全領域は左右 59・下 21・上 0
- 中身: 縮められる中身で、理想の大きさ 200 × 100 を求める SwiftUI の View
- 余白・移動量 (offset)・比率サイズは指定しない。基準領域と配置は各 Scenario のとおり
- 位置と大きさの比較の許容誤差は 0.5。折り返す本文の幅だけは 1.0 (折り返した行の幅と提案した幅の差を吸収する。core/ADR-0009 の共通ケース表の許容誤差と同じ)

## MODIFIED Requirements

### Requirement: 窓全体基準で端の軸に付けた SwiftUI の中身は、器と安全領域の重なりを標準の安全領域として受け取る

基準領域が窓全体のとき、iOS の器に載せた SwiftUI の中身は、端の軸の各辺について、重なりと等しい値を SwiftUI 標準の安全領域として受け取る SHALL。中身は、安全領域を避ける (既定) か無視する (`ignoresSafeArea`) かを SwiftUI の標準の書き方で選べる。

- 届けるのはシステムの領域 (ステータスバー・ホームインジケータ等、UIKit の safe area にあたるもの) だけで、キーボードの領域は含めない
- 中央の軸の辺では、重なりがあっても安全領域を受け取らない (0)
- 片側の端の軸で、中身が安全領域の内側に収まらないときは、その軸で内側の辺にそろって器いっぱいに置かれ、その軸の安全領域を受け取らない (0) (Requirement「窓全体基準で片側の端に付けた SwiftUI の中身が安全領域の内側に収まらないときは、内側の辺にそろって器いっぱいに置かれる」)
- 窓の寸法や窓の安全領域が表示中に変わったら、中身が受け取る値も新しい重なりになる
- KMP の Swift 面から登録した SwiftUI の中身も同じく受け取る

**Side Effects**: なし

### Requirement: 安全領域を受け渡しても、器の大きさと位置は変わらない

SwiftUI の中身の器の大きさと位置は、中身が受け取る安全領域に左右されない SHALL。器へ伝える要求サイズは、中身が安全領域を受け取らないときと同じ値である。端に付けた縮められる中身は器の内側で安全領域を避け、使える大きさが重なりの分だけ減る。

- 安全領域を無視する中身 (`ignoresSafeArea`) は、器の矩形も中身の位置と大きさも、安全領域を受け取らない場合と同じになる
- 安全領域の内側に収まらない中身の器の内側での並び方は、Requirement「窓全体基準で片側の端に付けた SwiftUI の中身が安全領域の内側に収まらないときは、内側の辺にそろって器いっぱいに置かれる」が定める。器の矩形は変わらない
- 中央に置いた中身は、安全領域に重なっても要求サイズより大きくならない
- 中身の要求サイズが表示中に変わったら、器はその新しい大きさに追従する
- UIView で書いた中身の扱いは変えない (UIKit の伝播で、重なりを safe area として受け取ったまま)

**Side Effects**: なし

## ADDED Requirements

### Requirement: 窓全体基準で片側の端に付けた SwiftUI の中身が安全領域の内側に収まらないときは、内側の辺にそろって器いっぱいに置かれる

基準領域が窓全体で、片側の端の軸に付けた SwiftUI の中身が、その軸で安全領域の内側に収まらないとき、中身はその軸で内側の辺にそろい、器いっぱいまで使って置かれる SHALL。

- 縮まない中身は、その軸で器に収まるなら器の矩形いっぱいに置かれる。器より大きいなら、内側の辺を器の内側の辺に合わせ、付いた側 (窓の端の外) へはみ出して置かれる。どちらも、位置は一番外側で安全領域を無視する指定の有無で変わらない
- 一部だけ縮む中身は、その軸で縮める限り縮んだうえで内側の辺にそろう
- 収まる中身 (縮められる中身) の並び方は Requirement「安全領域を受け渡しても、器の大きさと位置は変わらない」のまま (安全領域の内側に置かれる)
- 中身の一番外側やその内側から読める位置と大きさ (`GeometryReader`・`onGeometryChange` で読むもの) は、描かれた位置と一致する。収まる中身でも収まらない中身でも同じ
- 中身の理想の大きさ、または中身が受け取る安全領域 (窓の安全領域や寸法の変化による) が表示中に変わって、収まる / 収まらないが切り替わっても、器の矩形と中身の描かれた位置は新しい状態で落ち着き、行ったり来たりしない
- 両側の端の軸 (fill)・中央の軸・窓全体以外の基準領域では、並び方を変えない
- Dialog・Loading・Toast の SwiftUI の中身 (KMP の Swift 面から登録したものを含む) が対象で、UIView の中身は対象外

**Side Effects**: なし

#### Scenario: [PB-IS-35] 器より大きい縮まない中身は、内側の辺にそろって付いた側へはみ出す
- **GIVEN** 縦長の窓と、基準領域を窓全体にし、垂直の配置を下端 / 上端にした、固定サイズ 200 × 1000 の SwiftUI の中身の Dialog (器は窓の高さ 852 で頭打ちになる)
- **WHEN** Dialog を表示する
- **THEN** 器の矩形は y 0・高さ 852 で、中身の描かれた位置は下端なら y 0・高さ 1000 (窓の下端の外へ 148 はみ出す)、上端なら y -148・高さ 1000 (窓の上端の外へ 148 はみ出す) である。中身から読める位置も同じである

#### Scenario: [PB-IS-26] 窓全体基準で下端に付けた縮まない Loading・Toast の中身は、器いっぱいに置かれる
- **GIVEN** 縦長の窓と、基準領域を窓全体にし、水平の配置を全面 (fill)・垂直の配置を下端にした、[PB-IS-20] と同じ縮まない中身の Loading / Toast
- **WHEN** Loading / Toast を表示する
- **THEN** 器の矩形の下端は窓の下端 852 にあり、中身の描かれた位置は器の矩形と同じである

#### Scenario: [PB-IS-27] 両側の端と中央の軸、既定の基準領域では、並び方を変えない
- **GIVEN** 縦長の窓と、固定サイズ 200 × 100 の SwiftUI の中身の Dialog を、次の 2 通りで用意する: 基準領域を窓全体にして両軸を全面 (fill) にしたもの / 基準領域を指定せず (可視領域) 垂直の配置を上端・下端にしたもの
- **WHEN** Dialog を表示する
- **THEN** 全面のものは、中身の描かれた位置が y 388.5 (安全領域の内側の中央) である。可視領域のものは、器の矩形が上端なら y 59、下端なら y 718 で、中身の描かれた位置は器の矩形と同じである

### Requirement: 大きさを中身に委ねた軸は、有効領域の上限が広がると新しい上限まで広がる

器に載せた中身 (SwiftUI・UIView とも) の大きさを中身に委ねた軸は、表示中に有効領域の大きさが前より広がったとき、要求サイズを中身の理想の大きさから求め直し、理想の大きさと新しい有効領域の大きさの小さいほうまで広がる SHALL。有効領域が広がる場面は、添付値の到達で基準領域が窓全体になったとき ([PB-IS-15])・窓の回転・窓の寸法の変化である。

- 広がった後に有効領域が狭まったら、新しい有効領域で頭打ちになる (今と同じ)
- 求め直した後の器の矩形は落ち着き、行ったり来たりしない
- 有効領域の大きさが変わらないまま器が置き直されても (同じ寸法の窓での再レイアウトなど)、求め直さず、器の矩形は変わらない
- 有効領域が変わらない配置の器の矩形は、今と同じ値のまま
- Dialog・Loading・Toast の中身が対象

**Side Effects**: なし

#### Scenario: [PB-IS-28] 窓より広い理想の幅を持つ中身は、縦長から横長に変えると広がる
- **GIVEN** 縦長の窓に、基準領域を指定せず (可視領域)、両軸を中央に置いた、理想の幅 600 を求める SwiftUI の中身の Dialog が表示されている (器の幅は 393 で頭打ち)
- **WHEN** 窓を横長に変え、続けて縦長に戻す
- **THEN** 横長に変えた後の器の幅は 600 になり、縦長に戻した後は 393 になる。それぞれ 1 秒間変わらない

#### Scenario: [PB-IS-29] 中央に置いた長い本文は、縦長から横長に変えると有効領域の幅まで広がる
- **GIVEN** 縦長の窓に、基準領域を指定せず (可視領域)、両軸を中央に置いた、窓の幅を超える長さの本文 (折り返しを許す) を持つ SwiftUI の中身の Dialog が表示されている
- **WHEN** 窓を横長に変える
- **THEN** 器の幅は横長の有効領域の幅 734 になり、1 秒間変わらない

#### Scenario: [PB-IS-34] 有効領域で頭打ちになった本文は、同じ寸法の窓で置き直されても幅が変わらない
- **GIVEN** 横長の窓に、基準領域を指定せず (可視領域)、両軸を中央に置いた、窓の幅を超える長さの本文 (折り返しを許す) を持つ SwiftUI の中身の Dialog が表示され、器の幅が有効領域の幅 734 で落ち着いている
- **WHEN** 窓の寸法を変えずに、器の再レイアウトを 1 秒間繰り返し起こす
- **THEN** 器の矩形は 1 秒間変わらない

#### Scenario: [PB-IS-30] UIView の中身も、縦長から横長に変えると広がる
- **GIVEN** 縦長の窓に、基準領域を指定せず (可視領域)、両軸を中央に置いた、窓の幅を超える長さの本文 (折り返しを許す) を持つ UIView の中身の Dialog が表示されている
- **WHEN** 窓を横長に変える
- **THEN** 器の幅は横長の有効領域の幅 734 になり、1 秒間変わらない

#### Scenario: [PB-IS-31] Loading・Toast の中身も、縦長から横長に変えると広がる
- **GIVEN** 縦長の窓に、基準領域を指定せず (可視領域)、窓の幅を超える長さの本文 (折り返しを許す) を持つ SwiftUI の中身の Loading / Toast が表示されている
- **WHEN** 窓を横長に変える
- **THEN** 器の幅は横長の有効領域の幅 734 になる
