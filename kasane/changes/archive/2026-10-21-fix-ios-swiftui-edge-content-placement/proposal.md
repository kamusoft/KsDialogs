# Proposal: fix-ios-swiftui-edge-content-placement

## Why

iOS の器に載せた SwiftUI の中身を、基準領域を窓全体にして片方の端に付けると、2 つの不具合が出る。

1. 縮まない中身 (文言とボタンを並べた中身など) が、安全領域の重なりの半分だけ内側へずれる。下端に付けると 17、上端に付けると 29.5 ずれる。一番外側で安全領域を無視する指定を付けても、下端では戻らない。ios/ADR-0002 で器の大きさに重なりを足さないことにしたため、使える大きさが重なりの分だけ足りなくなる。そこへ SwiftUI が中身を安全領域の内側の中央に置くのが原因である。ColorAnalyzer の KMP 版の「下の確認」は、0.1.0-beta.5 でこの形になった。ColorAnalyzer のオーナーはこの見え方を許容しなかった (`exploration.md`)
2. 大きさを中身に委ねた軸の幅が、新しい上限まで広がらない。窓全体基準の折り返す本文は 734 で止まり、縦長から横長に回転しても 393 のまま広がらない。器が狭く置いた幅を中身が覚えて、そのまま要求し続けるのが原因である (簡易起票 `fix-swiftui-window-area-first-layout-width` を同梱)

方向は ios/ADR-0003 (proposed) と探索の決定事項による。1 は、収まらない中身を器の内側の辺にそろえる。2 は、上限が広がったら覚えた幅を捨てる。試作の実測で、1 の形が成り立つことを確かめた (`evidence/inner-edge-alignment-probe.md`)。

## What Changes

- 窓全体基準で片方の端に付けた軸 (配置 start / end。比率サイズの有無を問わない) で、安全領域の内側に収まらない SwiftUI の中身は、器の内側の辺にそろえて置く。縮まない中身は器いっぱいに置かれ、0.1.0-beta.4 と同じ位置になる。この位置は、安全領域を無視する指定の有無で変わらない。そろえる辺は物理の向きで決め、右から左に書く言語でも同じ辺になる。収まる中身 (縮められる中身) の並び方は今のまま
- 中身から読める位置 (`GeometryReader`・`onGeometryChange`) は、描かれた位置と一致する
- 大きさを中身に委ねた軸の上限が広がったら (添付値の到達で基準領域が窓全体になった・窓の回転・窓の寸法の変化)、中身の大きさを理想の大きさから求め直し、新しい上限まで広がる
- 対象は Dialog・Loading・Toast の SwiftUI の中身で、KMP の Swift 面から登録したものを含む。全面・中央の軸、窓全体以外の基準領域、器の矩形は変えない
- UIView の中身は変えない。ただし、幅が回転で広がることをテストで確かめる
- 影響する能力: ios-native
- 蒸留時に反映: decisions — ios/ADR-0003 を accepted にする。ios/ADR-0002 の footer に `関連: ios/ADR-0003` の行を足す
- 蒸留時に反映: concepts — `kasane/concepts/ios/api/layout-surface.md` を書き直す。「固定サイズの中身の注意」は、保証しない並び方から「収まらない中身は内側の辺にそろう」という保証に変える。「器の大きさは安全領域で変わらない」節から、幅が窓まで広がらない制約の段落を外す

## Non-Goals

- 中身ごとに安全領域を受け取らない指定 (公開 API) を足すこと: 探索で却下した (ios/ADR-0003 の Alternatives Considered)。指定を付けない中身のずれが残る
- 縮まない中身にシステムの領域を避けさせること: 器を大きくする必要があり、ios/ADR-0002 で却下した形 (安全領域を無視する中身の外形が変わる) に当たる
- Android の器の中身から見える insets を揃えること: 別の能力 (android) の話。簡易起票 `align-android-content-insets-meaning` で扱う
- 共通ケース表 (`core/layout-spec/cases.json`) へのケースの追加: 表の読み手が android/・maui/ にもある。今回の挙動は iOS の SwiftUI の中身だけの話なので、iOS のテストで固定する
- ColorAnalyzer 側の取り込み (版の更新と見た目の照合): 別リポジトリの作業
- `ui/` の brief・モックの作成: 新しい見た目を作るのではなく、0.1.0-beta.4 までの位置へ戻す修正のため。見た目の基準は探索で保存した原本の画像 (`ui/references/original-maui-bottom-confirm.png`) で、挙動はデルタスペックの位置の Scenario で固定する

## Impact

- 公開 API の変更は無い。見た目が変わるのは、窓全体基準で端に付けた縮まない SwiftUI の中身で、0.1.0-beta.4 までの位置に戻る。縮まない中身から見える安全領域は 0 になる (今は下 17・上 29.5 のような半端な値)
- 窓全体基準で大きさを中身に委ねた SwiftUI の中身は、幅が窓まで広がるようになる。[PB-IS-15] の器の幅は 852 になり、右端も安全領域に重なるので、中身は左右とも 59 を受け取る
- リスク: はみ出しの判定は、そろえが効いていない間に測り、器の大きさか中身の理想の大きさが変わるまで保つ。理想の大きさが変わって判定をやり直す瞬間に、位置が 1 回跳ねないかは未測定。テストで固定する
- リスク: UIView の中身が回転で広がることは、まだテストで確かめていない (コードの読みでは幅を覚える仕組みが無い)。成り立たなければ、同じ Requirement の範囲で直す
- リスク: はみ出していない間は、レイアウトのたびに大きさの問い合わせが 1 回増える。上限が広がったときの求め直しが行ったり来たりしないことも、テストで確かめる

## 級: M

iOS の単一の能力の不具合修正で、公開 API の変更は無い。ただし、観察できる約束 (Scenario) の見直しと追加を伴う。
