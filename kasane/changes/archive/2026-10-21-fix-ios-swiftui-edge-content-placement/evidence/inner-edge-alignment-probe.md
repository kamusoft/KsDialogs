# 実測: 収まらない中身を器の内側の辺にそろえる試作 (2026-10-21)

ios/ADR-0003 (proposed) の前提「SwiftUI のホストの中で中身を器の内側の辺にそろえて置けば、縮まない中身は器いっぱいに置かれ、縮められる中身は今までどおり安全領域の内側に収まる」を確かめるため、使い捨ての試作で測った。試作のコードはコミットしていない (測り終えて捨てた)。

## 条件

- 端末: iPhone 17 Pro / iOS 26.0 の Simulator。窓は 393 × 852 (安全領域 上 59 / 下 34)、横長は 852 × 393 (左右 59 / 下 21)。テスト用の窓 `ios/Tests/KsDialogsTests/Support/DialogLayoutTestWindow.swift` の上書き
- 中身の矩形は、描いた画素 (`layer.render` で塗りの外接矩形) と、中身に重ねた UIView の目印の窓座標の 2 通りで測り、全条件で一致した。`onGeometryChange` は包みを挟むと描画と食い違う場合があり、主な値に使っていない (下の「残ったずれ」)
- 固定直後から 1 秒間 (50 ms 間隔で 21 回)、器の矩形・中身の矩形とも全条件で 1 種類だけ
- 包みなし (変更前) の値は `kasane/changes/archive/2026-10-20-deliver-swiftui-content-safe-area-ios/evidence/safe-area-sizing-probe.md` と一致し、既存の 3 スイート (`DialogSwiftUISafeAreaTests`・`LoadingSwiftUISafeAreaTests`・`ToastSwiftUISafeAreaTests`) は 19/19 通った

## 試した形

- 器のレイアウトの解から、基準領域が窓全体・大きさを中身に委ねた軸 (比率も fill も無い)・位置が前端 / 後端の軸について付いた側を求め、ホストのルート (`DialogSwiftUIRoot`) へ渡す。前端に付いたら後端側、後端に付いたら前端側が内側の辺
- ルートで、その軸に `.frame(minHeight: 0, maxHeight: .infinity, alignment: 内側の辺)` (水平なら `minWidth: 0, maxWidth: .infinity`) を 1 つ挟む。全面 (fill)・比率・中央の軸には挟まない
- `min…: 0` が要る。`maxHeight: .infinity` だけでは描画が今と 1 画素も変わらない (伸び縮みする frame が子の大きさを下限にし、包みも縮まない大きさになって安全領域の内側の中央に置かれる)
- 包みの置き場所 (`ignoresSafeArea` の外側・内側・中身の直上・自作の Layout) は、全条件で結果を変えなかった

## 読み取れること

- 前提は成り立つ。縮まない中身は器いっぱい (安全領域を届けていなかった 0.1.0-beta.4 と同じ位置) に置かれ、無視する指定の有無で位置が変わらない。縮められる中身は安全領域の内側に収まる。全面・中央・既定の可視領域は変わらない。Loading・Toast も Dialog と同じ
- 残ったずれ: 縮められる中身でだけ、`onGeometryChange` の `frame(in: .global)` が器いっぱいの値 (y 0 h 100 / y 752 h 100) を返し、描画 (y 59 h 41 / y 752 h 66) と食い違う。既存テストでは [PB-IS-10] の 2 ケースがこれで落ちる。ホストのレイアウトの走らせ直し・`sizeThatFits` の呼び出しでは変わらず、原因は未特定。縮まない中身では一致した
- 測り方の注意: `maxHeight: .infinity` だけの包みでは `onGeometryChange` が期待どおりの値を返す一方で描画は動いていなかった。この種の実測は画素か UIView の目印で見る
- 未測定: 右から左に書く言語での水平の端、比率サイズで端に付けた軸

## 追加の実測: geometry のずれ・右から左 (2026-10-21)

条件と測り方は上と同じ。右から左は `window.traitOverrides.layoutDirection = .rightToLeft` と、中身にだけ `.environment(\.layoutDirection, .rightToLeft)` の 2 通り。

### geometry のずれは利用者に見える

縮められる中身 (200 × 100、上端 / 下端、無視なし) で、上の形 (常に `min 0 / max ∞` の frame) と変更前を比べた:

| 見たもの | 変更前 | 上の形 |
|---|---|---|
| 描画 | y 59 h 41 / y 752 h 66 | 同じ |
| 利用者の `GeometryReader` の値で描いたもの | size 41 / 66・上 59 / 下 34 | 同じ |
| `GeometryReader` の最後に評価された body の値 | 41・上 59 / 66・下 34 | 100・y 0 / y 752・安全領域 0 |
| `onGeometryChange` (中身の直上・内側の子・一番外側の 3 か所) | 41 / 66 | 3 か所とも 100 |

- 値を外へ書き出す使い方 (`onGeometryChange`・`@State` への書き込み) では、器いっぱい・安全領域 0 の値が最後に届き、描画と食い違う。`kasane/concepts/ios/api/layout-surface.md`「`GeometryReader` で読む値」の約束が崩れる
- 当たり判定は区別できなかった (ホストの View の `hitTest` は、変更前・試作ともホストの境界内ならどこでもホスト自身を返す)
- ずれは、縮められる中身を `min 0 / max ∞` の frame か自作の Layout で包んだときだけ起きる。全部 nil の frame では起きない。原因は未特定 (ずれた通知は `_UIHostingView.layoutSubviews` から描画を経た経路で来る。ホストの `sizingOptions` を空にしても同じ)

### 試した形と結果

| 形 | 縮められる中身で geometry と描画が一致 | 縮まない中身が内側の辺にそろう | 右から左 | 中身の作り直し |
|---|---|---|---|---|
| 常に `min 0 / max ∞` の frame (置き場所 3 通り・自作 Layout・`sizingOptions = []` を含む) | ✗ | ○ | ✗ (逆側へ寄る) | なし |
| 同上 + 物理の向きへの変換 | ✗ | ○ | ○ | なし |
| はみ出すときだけ提案の大きさを返す自作 Layout | ✗ | ○ | ○ | なし |
| 包みなし、はみ出す軸だけ安全領域を無視させる | ○ | ✗ (下端・右端で効かない。y 735 / x 622.5) | — | なし |
| はみ出すときだけ包みを `if` で差し込む | ○ | ○ | ○ | あり (`@State` が消える) |
| **frame を常に挟み、はみ出す軸でだけ `min 0 / max ∞` と内側の配置を入れる (それ以外は全部 nil)** | **○** | **○** | **○** | **なし** |

最後の形 (以下「はみ出す軸だけの包み」) の要点:

- はみ出しの判定は、包みが効いていない間だけ測る (ホストに、置かれた幅 + 左右の安全領域・器の高さを提案して答えから安全領域を引き、器から重なりを引いた大きさと比べる)。包みが効いた状態で測ると包みがはみ出しを隠し、判定が行ったり来たりする。そのため一度はみ出しと決めたら、器の大きさか中身の理想の大きさが変わるまで保つ
- 内側の配置は、ルートで書字方向を読んで物理の左右へ変換する (`.leading` / `.trailing` のままだと、右から左の窓で逆側へ寄り、器から 59 はみ出す)

はみ出す軸だけの包みでの再確認 (器の矩形は全条件で変更前と同じ、1 秒間 1 種類だけ):

- 帯の下端 (無視なし / あり): y 737.5。固定 200 × 100: 上端 y 0 / y 0、下端 y 752 / y 752
- 縮められる中身: y 59 h 41 / y 0 h 100 / y 752 h 66 / y 752 h 100 (変更前と同じ)。geometry も描画と一致
- 一部だけ縮む中身 (最小の高さ 80): 変更前は上端 y 39.5・下端 y 745 → 上端 y 20 h 80・下端 y 752 h 80 (最小まで縮んで内側の辺にそろう)。geometry も一致
- Loading・Toast の帯: y 737.5。全面 y 388.5、中央 800 は y 26、既定の可視領域 y 59 / y 718 (変わらない)
- 右から左: 水平 end x 652、start x 0 (物理の内側の辺)。縮められる中身は変更前と同じ
- 既存テスト: テストターゲット全体 402 件 / 67 スイートがすべて通る (上の形では [PB-IS-10] の 2 件が落ちていた)

未測定: 理想の大きさが変わって判定をやり直す瞬間に、1 回だけ包みなしで描かれて位置が跳ねないか。はみ出していない間、レイアウトのたびに大きさの問い合わせが 1 回増えるコスト
