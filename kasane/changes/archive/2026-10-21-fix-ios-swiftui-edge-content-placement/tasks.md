# Tasks: fix-ios-swiftui-edge-content-placement

実装の形の当たりは `evidence/inner-edge-alignment-probe.md` にある (試作で成り立った形と、成り立たなかった形の理由)。特に次の 3 点は試作で確かめた。

- 包みは常に挟み、はみ出す軸でだけ効かせる。はみ出すかどうかに関係なく `min 0 / max ∞` の frame で包むと、縮められる中身で geometry が描画と食い違う。`if` で差し込むと中身が作り直される
- そろえる辺は物理の向きで渡す
- はみ出しの判定は、包みが効いていない間に測って保つ

## 1. 収まらない中身の内側の辺へのそろえ

- [x] 1.1 器のレイアウトの解から、窓全体基準で配置 start / end の軸 (比率サイズの有無を問わない) について、付いた側を物理の向き (上下・左右) で求め、SwiftUI の中身のホストへ渡す。全面 (fill)・中央の軸と窓全体以外の基準領域では渡さない。レイアウトの解では fill も前端に固定される (`Layout/DialogLayoutResolver.swift` の `resolveAxis`) ので、fill と start を見分けられる形で渡す (→ Requirement: 窓全体基準で片側の端に付けた SwiftUI の中身が安全領域の内側に収まらないときは、内側の辺にそろって器いっぱいに置かれる)
- [x] 1.2 ホストのルートに、はみ出す軸でだけ「縮められる限り縮め、内側の辺にそろえる」を効かせる包みを常に挟む。はみ出さない軸では包みは何もしない。内側の辺は書字方向を読んで物理の左右へ変換する (→ 同上)
- [x] 1.3 はみ出しの判定を、包みが効いていない状態の大きさで行い、器の大きさ・中身の理想の大きさ・中身が受け取る安全領域 (重なり)・そろえる軸と辺のどれかが変わるまで保つ。判定をやり直す瞬間に位置が跳ねないことを確かめる (→ 同上・Scenario [PB-IS-25]・[PB-IS-33])
- [x] 1.4 Dialog のテストを書く・直す: [PB-IS-20]〜[PB-IS-25]・[PB-IS-27]・[PB-IS-32]・[PB-IS-33]・[PB-IS-35] を足し、[PB-IS-12] を中身の描かれた位置まで見る形に直す。[PB-IS-10] は描かれた位置 (画素か、中身に重ねた UIView の目印) で測る形に直す。中身から読む値 (`onGeometryChange`) だけで位置を判定しない — 試作で、描画が動いていないのに期待どおりの値を返す形があった (→ Requirement: 安全領域を受け渡しても、器の大きさと位置は変わらない / 窓全体基準で片側の端に付けた SwiftUI の中身が…器いっぱいに置かれる)
- [x] 1.5 Loading・Toast のテストを書く: [PB-IS-26] (→ 窓全体基準で片側の端に付けた SwiftUI の中身が…器いっぱいに置かれる)
- [x] 1.6 既存の [PB-IS-01]〜[PB-IS-09] (Loading・Toast の [PB-IS-05]・[PB-IS-06] を含む) が変更後も通ることを確かめる (→ Requirement: 窓全体基準で端の軸に付けた SwiftUI の中身は、器と安全領域の重なりを標準の安全領域として受け取る)

## 2. 上限の拡大への追従

- [x] 2.1 器から中身へ、大きさを中身に委ねた軸の有効領域の上限を知らせる内部の経路を足す。SwiftUI の中身は、前に知らされた上限より新しい上限が広がったときだけ、覚えた幅を捨てて理想の幅から要求サイズを求め直す (覚えた幅との比較にしない — 頭打ちの本文は上限よりわずかに狭い幅 (733.33 / 734) で落ち着くため、同じ上限の通知で求め直しを繰り返してしまう)。上限が変わらない置き直しでは何もしない (→ Requirement: 大きさを中身に委ねた軸は、有効領域の上限が広がると新しい上限まで広がる)
