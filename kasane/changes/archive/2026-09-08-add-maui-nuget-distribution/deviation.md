# 実装乖離メモ: add-maui-nuget-distribution

- Scenario「BG8401 の不在と static メンバーの可用性」(tasks 1.1): design Decision 5 では `.Companion` 入れ子型と同名 static フィールドの両方を `remove-node` → 実装では入れ子型は `attr visibility=private`、static フィールドのみ `remove-node` のハイブリッド。理由: 両方を `remove-node` にすると生成器が metadata を 2 度目に当てる際に「対象が既に無い」BG8A00 が 8 種出て警告総数が増える。ハイブリッドでは BG8A00 4 種 (BG8401 と同数) に留まり、生成コードから Companion は消える。spec の受け入れ条件 (BG8401 の不在・facade のビルド成功) は満たす。0 警告にする手段 (入れ子型を managedName で改名して束縛したまま残す) は「輸送層から落とす」意図に反するため採らず、ハイブリッド (BG8A00 4 種を受容) をオーナー裁定で確定 (2026-09-08)
- Requirement「3 パッケージの構成と内容」の自 assembly 用 aar (tasks 2.2 / 3.3): design Decision 1 は翻案元の実測から「.NET Android SDK が生成する自 assembly 用 aar (`KsDialogs.Maui.aar` / `KsDialogs.Binding.Android.aar`) を後処理で除く」前提 → KsDialogs では Release / Debug のどの出力にも生成されず、除去後処理 (`KsExcludeGeneratedAarFromPackage`) は `Exists` 条件が不成立で走らない。spec の「nupkg に含まれない」は同梱物の実測で満たす。後処理は SDK 挙動が変わったときの保険として翻案元と同形のまま残す (中身の許可パターンは KsDialogs では未評価)。利用者側の `XA4301` 不在は消費者検証 (tasks 5.2) で確認する (2026-09-08)
- [付随修正] `kasane/handbook/cross/test-execution.md` の実測表 (maui/ 155 件・maui/android/native 31 件、2026-09-07) と本文の「この 31 件」を、本変更後の実測 (160 件 / 34 件、2026-09-08) へ更新。同文書が「実態が変わったら実測で更新する」と定めるため (verify-001 の指摘、2026-09-08)
