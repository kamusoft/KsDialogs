# Exploration: fix-ios-toast-presentation-wait-flake

## 課題 / 動機

iOS のテスト全件実行 (`xcodebuild test -scheme KsDialogs`) で、Toast の提示待ちを含むテストが稀に 5 秒タイムアウトで落ちる。add-toast の修正サイクル中、計 9 回の全件実行のうち 2 回で発現 (落ちたのは `ToastContractTests` TS-CO-01 / `ToastSwiftUIContentTests` TS-IO-02 / `ToastTransitionTests` TS-TR-01 の `waitUntilPresenting` 到達)。単独・再実行では通り、同一ソースで 4 回連続全通過も確認済みのため、実装の欠陥ではなくホスト負荷起因のタイミング感受性と見られる (並行して Android instrumented・Gradle・dotnet build が走っていた時間帯に発現)。

待ち条件は `DialogTestWaiting.waitUntil` の 5 秒固定タイムアウトで、Simulator の起動直後・ホスト高負荷時にはアニメーション/ランループの進みが遅れて足りないことがある。

発見の文脈: add-toast 修正サイクル1周目の全件実行 (Loading/Dialog 例外境界修正ワーカーの報告)。関連する既存教訓: `kasane/lessons/inbox/test-instability-check-host-load-first.md` (テスト不安定はまずホスト負荷を疑う)。

## 検討した選択肢 (却下案と理由を含む)

- **原因を分離してから最小修正を選ぶ** — 採用。クリーンなホストと負荷下で反復し、環境汚染と Toast 固有の待ち不足を分離してから修正方針を決める。調査時間は増えるが、iOS テスト全体へ共有される待ち時間を根拠なく延長せずに済む
- **Toast テストだけ防御的に待ち時間を延長する** — 却下。影響を Toast に閉じられる一方、対応済み実行条件で再現せず、根因未確定のまま待ちを延ばす根拠がない
- **iOS テスト全体の待ち時間を延長する** — 却下。`DialogTestWaiting.waitUntil` の既定値は Dialog / Loading / KMP / Interop / SwiftUI を含むテスト基盤全体に波及し、失敗検出も遅くなる
- **提示待ちをより早い観測点へ変える** — 却下。現行 `waitUntilPresenting` もコンテナ割り当てを観測しており、器の取り付けより前に成立する。さらに早い観測へ弱めても、presentation フック開始・window 取り付け等の保証は固定できない
- **実装修正を行わず、探索記録を保持する** — 採用。対応済み実行条件で計 14 回再現せず、タイムアウトや観測条件を変える根拠が得られなかった。調査過程と見送り理由は再発時の比較材料になるため `exploration.md` を破棄しない

## 決定事項

- 2026-09-04: クリーンなホストと負荷下で原因を分離し、結果に応じて最小の修正を選ぶ。負荷条件の実測前にタイムアウト値や観測点を変更しない
- 2026-09-04: CPU 負荷だけでは再現しなかったため、iOS 全件テストと別ビルドルート 1 本の安全な並走で、実ビルド競合まで追加確認する。Android 系 Gradle 同士の同時実行は禁止規約に従って行わない
- 2026-09-04: 製品コード・テストコードとも修正しない。再現調査と見送り判断の根拠を保持するため、この `exploration.md` は破棄しない
- 2026-09-04: 実装修正なしで探索を完了し、調査証拠を保持したまま `ksn-distill` で archive する

## 調査結果

- 2026-09-04、12 論理 CPU のホストで、過去事例にあった孤児 `yes` プロセスが存在しないことを確認した。基準状態の load average は約 5.7。iOS 26.5 の iPhone 17 Pro Simulator で `xcodebuild test -scheme KsDialogs` を実行し、件数を取得した 4 回はすべて 251 tests / 47 suites で成功した。テスト本体の所要時間は 11.250〜11.620 秒、平均約 11.49 秒
- 同じ端末・同じ HEAD で、テスト実行中だけ `yes` 10 本を起動する CPU 負荷条件を 5 回反復した。5 回すべて 251 tests / 47 suites で成功し、テスト本体の所要時間は 11.674〜12.116 秒、平均約 11.91 秒。終了後に `yes` が残っていないことを確認した
- iOS 全件テストと `maui/KsDialogs.slnx` の非増分ビルドを並走した。成否を両側で確認できた 4 回は、MAUI ビルドがすべて成功し、並走中の iOS も 251 tests / 47 suites ですべて成功した。iOS テスト本体の所要時間は 11.202〜11.518 秒、平均約 11.37 秒で、基準状態より遅くならなかった。要約抽出を誤った初回も iOS 251 件は 11.260 秒で成功している
- 以上から、一般的な CPU 負荷と、安全な別ビルドルート 1 本の並走では既報の 5 秒タイムアウトを再現できず、タイムアウト一律延長の根拠にはならない。既報時は規約で禁止されている Android 系 Gradle 同士の並走を含んでおり、その条件をテスト側で吸収すべき根拠もない。低頻度のスケジューリング揺らぎは完全には否定できないが、現 HEAD の対応済み実行条件では計 14 回の件数確認済み全件実行が連続成功した
