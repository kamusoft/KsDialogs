# Deviation: revisit-dialog-margin-default

- tasks 2.1 / 2.2 (既定 Toast の余白 24 を添付する箇所): tasks では「ToastCoordinator の Builtin (`.builtin`) の分岐で作る `ToastDefaultContentView` に添付する」→ 実装ワーカーの判断により、両 Native の `ToastDefaultContentView` が初期化の中で自分に余白 全辺 24 の options (`attachedOptions`) を添付する形にした。Builtin の分岐で作られる View に余白が付く結果は同じで、spec (Requirement: 配置属性と ToastStyle「デフォルト View は、ライブラリがその中身に dialogMargin 全辺 24 を添付して持つ」) は満たす。理由: core/ADR-0039 の「同梱のピルが自分の性質として余白を持つ」に合い、Android の TS-AT-05 を測定ハーネスで作った View に対しても本番と同じ添付で検証できるため (2026-09-27)
- Requirement: 配置属性と ToastStyle / Scenario [TS-AT-05]: spec では「デフォルト View の左右の端は、可視領域の左右の端からそれぞれちょうど 24 内側にある」→ 指示により、iOS は「端は 24 より外に出ず、余りは 1 字幅の半分未満」と読み替えて受け入れる (Android はちょうど 24 のまま)。iOS のデフォルト View は折り返した最長行の幅まで縮んで中央に寄るため、端は 24 + (余白の内側の幅と最長行の幅の差の半分) に来る (実測: 期待 124 / 実測 127)。iOS のテストは許容差を「1 字幅の半分 + 1」として判定し、余白の添付が無い場合 (端が可視領域の端に来る) とは見分けられる。理由: proposal の「既定 Toast は変わらない」を守り、iOS の既定 Toast の見た目を変えないため。蒸留で concepts に書くときはこの読み替えの形で書く (2026-09-27)
