# MAUI 実配置テストホスト (maui/KsDialogs.Maui.PlacementHost) の KSDPLACEMENT 行の抜粋
# 端末 (1〜3): Android エミュレータ (API 35、密度 2、画面 720x1280 px。この実測のために別に boot した AVD) / iOS Simulator (iPhone 17、iOS 26.5。起動中の既存デバイスとは別に作成して boot)
# Android は logcat、iOS は simctl launch --console-pty の出力から KSDPLACEMENT 行だけを抜いた。生ログは手元保管
# 位置のシナリオの dialog=/area= は OS の単位 (Android は画面座標 px、iOS は window 座標 pt)。大きさのシナリオの shown=/expected=/rootBounds= は MAUI の単位 (dp / pt)
# 大きさのシナリオの合否: 表示されたルートの矩形 (shown) と、ルート自身の Width x Height (rootBounds。MAUI の配置が届いていなければ -1) がどちらも宣言サイズ (最小値指定では最小値) と許容差内で一致すること
# proportional-fill は幅を比率 0.8・高さを fill にしたダイアログ。outer= は外形 (器が中身として受け取る View) の矩形、root= はルートの矩形 (どちらも OS の単位)。
#   外形が契約どおり (幅 = 可視領域の幅 x 0.8、高さ = 可視領域の高さ - 余白 24 x 2) で、ルートが宣言サイズのままその中央に置かれることも合否に入れている

## 観測 (比率指定・fill の軸): 修正後は両 OS とも、外形は契約どおりの大きさになり、WidthRequest / HeightRequest を明示したルートは宣言サイズ (160x100) のまま外形の中央に置かれる。修正前の Android ではルートが外形いっぱい (288x544 dp) に広がっていた (1 と 2 の size-dialog-contentview-proportional-fill の行)
