- 追加した 3 検査は `calls`(= `cat`) を読むだけで台本を消費しないため、既存検査の入力を一切変えない。

  この 2 種を取り逃がす
- 逆に新設の回数検査だけが発火するのは上限判定の撤去 (NG 2) のみ。狙いどおり空白を埋めている

## 指摘事項

### [🟡 Minor] 根治が入る前の挙動を語るコメントが 2 箇所残っている (review-003 Minor-3 の適用漏れ)

**該当箇所**: `scripts/release/central-portal.sh:634-637` と `:445-448`

**問題点**:

review-003 が名指しした `:560-565` は二層の説明に直った。しかし同じ「`""` 分岐が入る前の世界」を
根拠として語るコメントが 2 箇所そのまま残っており、いずれも**現在のコードでは成り立たない**。

**(1) `:634-637`** — 検査「台本が尽きても…」の直前:

> 台本が尽きた照会は応答の得られない照会として扱われ、**待機は上限で失敗に落ちる**。

現在は落ちない。答えの返らない照会は `cmd_wait_published` の `""` 分岐 (`:304-308`) がその場で止めるため、
待機は上限に到達しない。**6 行下の検査名がそれをそのまま否定している** —
「答えの返らない照会は待たずに止まる (**上限まで空回りしない**)」(`:642`)。
同じ画面の中でコメントと検査名が正反対のことを言っている。

**(2) `:445-448`** — モックの台本切れ処理:

> 戻り値だけで失敗を伝えると、`if` の条件のように set -e が働かない文脈から呼ばれたときに
> 呼び出し側が空の応答を状態として扱い、**待機が上限まで空回りして自己テストが終わらなくなる**。

これも現在は起きない。実測 (スイープ「台本切れを『戻り値 1』へ戻す」): **緑 / 2 秒 / 停止なし**で、
回数検査も期待どおり 2 件を保つ。`return 1` でも `response` が空 → 非 200 → `fail` → `""` 分岐で止まるため、
`000` ステータスを返す設計はいま挙動を何も変えていない (二重の守りとして持つのは妥当だが、
「これが無いと終わらなくなる」という理由づけはもう真ではない)。

どちらも `comment-policy.md` の禁止する記述類型「アーカイブされた過去仕様の説明 — 現在の仕様を現在形で
書く」に当たる。機械検査 (`comment-policy-lint.py`) はこの型を検出しないため、規約本文からの判定になる
(同文書「検出 0 件は適合の証明にならない」)。

なお、review-003 が Minor-3 で心配した実害の経路 (この説明を信じて `""` 分岐を「死んだ分岐」として
落とす) は、今回の回数検査が塞いだ。残っているのは読み手を誤らせる説明そのもので、挙動のリスクは無い。
それでも 3 箇所のうち 1 箇所しか直っていないのは、合意済みの修正の適用漏れである。

**推奨修正**: `:560-565` と同じ二層の語り口に揃える。

- `:634-637` — 「台本が尽きた照会は答えが返らないので、`cmd_wait_published` が待機対象に残さずその場で
  止める。短い上限はその外側の保険で、`if` の条件では set -e が働かないため、余分に照会する誤った実装でも
  停止ではなく失敗として表れるようにする」といった形。直下の 2 検査 (終わり方 + 回数) の役割分担が読めること
- `:445-448` — 「台本切れは応答が返らなかったことにして、応答を解釈する側の失敗経路へ流す。
  ステータスとして返すことで、戻り値を見ない呼び出し経路でも成功にも既知の状態にも当たらない」のように、
  現在形の設計説明に書き直す (「これが無いと終わらなくなる」を理由にしない)

`deviation.md` の `[自己テストの構造]` は今サイクルで二層の説明に揃っており、こちらは修正不要。
