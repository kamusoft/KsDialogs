# 実測: SwiftUI の中身に標準の安全領域を渡したときの器のサイズ (2026-10-20)

phase-1 (`ios-safe-area-and-kmp-int-result/phase-1-ios-swiftui-content-safe-area`) の論点「サイズ計算の実測」の記録。ios/ADR-0002 の前提 (ホストに安全領域を渡しても器のサイズ計算が崩れない) を確かめるため、使い捨てのテストで測った。テストのコードはコミットしていない (測り終えて削除した)。

## 条件

- 端末: iPhone 17 Pro / iOS 26.0 の Simulator (`<udid>`)。`xcodebuild test -only-testing:` で 1 スイートだけを実行し、`Test run with 1 test in 1 suite passed` を確認した
- 窓: 393 × 852 pt。安全領域はテスト用の窓 (`ios/Tests/KsDialogsTests/Support/DialogLayoutTestWindow.swift`) の上書きで上 59 / 下 34 / 左右 0
- 中身: SwiftUI の固定サイズの中身 (幅 200、高さ 100。「中央・背の高い中身」だけ高さ 800)。基準領域は窓全体 (`.window`)。配置は show の引数で渡した
- 比べた設定: ホストの安全領域の扱い (`DialogSwiftUIHost.swift` の `safeAreaRegions`) を、今の `[]` (渡さない) と `.container` (システムの領域だけ渡す。キーボードは含めない) の 2 つ
- 器の大きさは、実効値の固定直後と、その後 1 秒間 (50 ms 間隔で 20 回) に測った。全条件で固定直後と 1 秒間の値は 1 種類だけで、行ったり来たりは無かった
- 「無視あり」は中身の一番外側に安全領域を無視する指定 (`.ignoresSafeArea(.container)`) を付けたもの

## 結果

器の中身の矩形 (窓の座標、y と高さ) と、ホストの View から見える安全領域:

| 配置 | 中身 | 今 (`[]`) の矩形 | `.container` の矩形 | ホストの安全領域 (上 / 下) | SwiftUI の中身から見える安全領域 (`[]` → `.container`) |
|---|---|---|---|---|---|
| 上端 (`start`) | 無視なし | y 0, 高さ 100 | y 0, 高さ **159** | 59 / 0 | 0 → 上 59 |
| 上端 (`start`) | 無視あり | y 0, 高さ 100 | y 0, 高さ **159** | 59 / 0 | — |
| 下端 (`end`) | 無視なし | y 752, 高さ 100 | y 718, 高さ **134** | 0 / 34 | 0 → 下 34 |
| 下端 (`end`) | 無視あり | y 752, 高さ 100 | y 718, 高さ **134** | 0 / 34 | — |
| 全面 (`fill`) | 無視なし / あり | y 0, 高さ 852 | y 0, 高さ 852 (変わらない) | 59 / 34 | 固定サイズの中身は中央にあり 0 |
| 中央 | 高さ 100 | y 376, 高さ 100 | y 376, 高さ 100 (変わらない) | 0 / 0 | 0 |
| 中央 | 高さ 800 (安全領域に重なる) | y 26, 高さ 800 | y 0, 高さ **852** | 59 / 34 | 0 → 途中経過のみ |
| 中央 | 高さ 800・無視あり | y 26, 高さ 800 | y 0, 高さ **852** | 59 / 34 | — |

UIView で書いた同じ大きさの中身 (今のコード) は、どの配置でも要求どおりの大きさのまま (上端 y 0・高さ 100 で safe area 上 59、下端は下 34、中央 800 は上 33 / 下 8)。UIView の中身には器と安全領域の重なりがすでに届いている。テスト用の窓の安全領域の上書きは、器の View を経てホストの View まで届いた (UIView の中身・ホストの View とも上の値を返した)。

## 読み取れること

1. ホストに安全領域を渡すと、ホストが器へ伝える要求サイズに重なりの分がそのまま足される。足される量は中身が安全領域を無視するかどうかに関係しない (無視ありでも上端 159・下端 134)
2. 端に付けた配置 (上端・下端) では大きさは 1 回で決まり、行ったり来たりしない。無視なしの中身はこれで SwiftUI 標準どおり安全領域の内側に寄る。無視ありの中身も器の外形が重なりの分だけ大きくなり、固定サイズの中身はその中で位置が動く (委任状の見た目の基準「安全領域を無視する指定があれば寄らない」に合わない)
3. 中央に置いた中身が安全領域に重なると、要求サイズが増える → 中央に置き直すと重なりが増える → さらに増える、を繰り返し、器の最大 (窓の高さ 852) まで膨らんで止まる (要求 800 に対して 852)。行ったり来たりはしないが「膨らみすぎ」に当たる。今はこの配置で見た目が変わらない
4. 全面 (`fill`) は大きさを器が決めるので変わらない。ColorAnalyzer で問題になった形 (窓全体を覆う中身) はこの配置で、ここは前提どおり
