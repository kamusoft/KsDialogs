## Context

core/ADR-0007 は「属性セットは原典踏襲の命名、規則を core 仕様に1本化」と方針を決め、属性の取捨を後続の仕様化作業に委ねた。その仕様化に先立つ原典実装の実測調査で、原典 AiForms.Maui.Dialogs のレイアウト属性は大半が素直である一方、実装都合の歪みが特定箇所に集中していることが判明した: Android の Offset 符号反転 (End 配置時)、DialogMargin が最大サイズ算出にしか効かない穴、Border の内容領域の iOS/Android 差、UseCurrentPageLocation の垂直方向のみの半端実装、OverlayColor 透明時のステータスバー暗転を避ける Android ハック、動的リサイズの iOS 非対応 (真の課題は描画後 VM Bind で内容依存の高さが反映されないこと)。

属性の取捨そのものは core/ADR-0014 が確定した (契約に残すのは器のメタ属性のみ。起票時の「コア属性を全て残す」は同 ADR が改訂)。本 ADR は、契約に残った属性について**原典との意図的乖離**を定める。

## Decision

契約に残る属性 (core/ADR-0014 の10個) は原典踏襲を基本とし、以下を原典からの**意図的乖離**として確定する:

1. **Offset 座標系の統一**: 常に「+X 右 / +Y 下」。原典 Android の End 配置時符号反転は仕様バグとみなし継承しない
2. **DialogMargin は位置決めにも効く**: 最大サイズ制約に加え、Start/End 配置時に端から Margin 分離れる。直感との一致を原典挙動の継承より優先する
3. **UseCurrentPageLocation は enum `LayoutArea { window, visibleArea }` に再設計して維持**: 両 OS とも垂直方向にしか効かない半端実装を正し、水平・垂直の両軸で効かせる。visibleArea = システムバーを除いた可視領域 (iOS = safe area / Android = システムバー除外領域)。bool では基準が名前から読めないため enum とし、将来第3の基準を既存指定を壊さず足せる形にする。「システムバー以外の部分の座標で指定したい」ニーズは外せないため廃止しない
4. **OverlayColor 透明時の正式対応**: Android で透明指定時にステータスバーだけ暗転する問題は、原典のハック的回避 (Gravity=Bottom 切り替え + padding 補正) を継承せず、透明のときだけ配置規則が変わる特殊分岐を持たない形で正式に対応する
5. **初期サイズは初回レイアウトパス完了時点で確定**: 原典の動的リサイズ機構 (iOS 非対応の片肺) は継承せず、「描画後に VM が Bind され内容依存の高さが反映されない」という真の課題を初期化順序 (VM 初期状態の適用 → 初回ネイティブレイアウトパスでの内容サイズ確定 → 提示) で解決する。Bind 後の継続的な動的リサイズは範囲外
6. **既定値の乖離3件**: dialogMargin = 全辺 24 (原典 0)・overlayColor = 黒 40% (原典 Transparent)・layoutArea = visibleArea (原典は window 相当が既定)。いずれも現行実装の挙動をそのまま既定として維持するためのオーナー判断で、「属性を何も指定しなければ今までどおりに出る」を全 OS で成り立たせる
7. **isCanceledOnTouchOutside は原典既定 true を踏襲し、規則を次のとおり定める**: true (既定) のとき、ダイアログ外形 rect の外側 (オーバーレイ領域を含む) へのタップで、キャンセル操作と同一の経路 (`cancelled` 結果) でダイアログを閉じる。false のとき外側タップは何も起こさない (イベントはオーバーレイが吸収し背後へ透過しない — モーダル性を保つ)。ダイアログ内側のタップはこの機構に関与しない。overlayColor の値 (透明含む) と独立に機能する。現行実装には外側タップ機構自体が無く要件漏れの新規導入のため、既定は「現行維持」ではなく原典踏襲を基準とする
8. **対象外の整理**: AutoRotateForIOS はレイアウト属性ではなく回転挙動であり、本 ADR の範囲外の別論点へ送る。起票時に定めた「Border は内側描画に統一」は、core/ADR-0014 による Border 属性自体の廃止で無効

## Alternatives Considered

- **完全な原典互換 (歪みごと踏襲する案)** — 却下。Offset 符号反転や DialogMargin の穴は共通仕様テストで「OS 差・歪みを仕様化」する羽目になり、ADR-0007 の弱点 (規則文の曖昧さがそのまま実装差になる) を直撃する
- **UseCurrentPageLocation を落とす案** — 却下。システムバー除外領域基準で位置指定したいニーズは外せない (オーナー判断)
- **動的リサイズの完全継承案** — 却下。原典でも iOS 非対応の片肺であり、show 毎回生成モデル (core/ADR-0005) では Bind 後の継続リサイズの需要が低い。初期化順序の是正で真の課題のみ解決する
- **外側タップで dismissed など第3の結果種別を導入する案** — 却下。結果通知の型契約 (core/ADR-0003) に新しい結果種別を増やすことになり、原典も cancel と同経路
- **isCanceledOnTouchOutside の既定を false (安全側) にする案** — 却下。原典既定 true からの乖離に「現行挙動の維持」以外の理由がない (現行実装には機構自体が無く、維持すべき現行挙動が存在しない)

## Consequences

- 正: 属性の意味が全 OS で一貫し、共通仕様テストの期待値が1本の規則文から導ける
- 正: 原典ユーザーは属性名 (改名した layoutArea を除く) そのままで移行でき、挙動差は「歪みが直った」方向に限定される
- 正: 既定値時の見た目は現行実装と一致し、属性未指定の既存呼び出しはソース互換・視覚互換を保つ
- 負: 原典と目に見えて挙動が変わる箇所 (DialogMargin の位置決め適用・Android End 時 Offset) があり、移行ガイドでの明記が必要
- 負: LayoutArea 再設計と OverlayColor 正式対応は原典に手本がなく、設計・検証コストを新規に払う
- 負: 外側タップは既定 true で新規に cancelled を返すため、属性未指定でも操作面だけは現行実装から挙動が1つ増える
