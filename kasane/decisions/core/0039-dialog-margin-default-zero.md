## Context

core/ADR-0008 は、器のメタ属性の既定値のうち 3 件を原典から意図的に乖離させた。その 1 件が余白 (dialogMargin) で、原典の 0 に対して全辺 24 とした。理由は「契約を導入する前の実装の挙動を既定として維持し、属性を何も指定しなければ今までどおりに出る」ことだった。

- add-page-layout-area の Sample 撮影証跡を見たオーナーが、ダイアログが基準領域の端から 24 離れて出るため、配置 (先頭寄せ・末尾寄せ) と基準領域の効き方をぱっと見で確かめにくいと指摘した。同 change では Layout Dialog パネルのダイアログにだけ全辺 0 を明示して回避した
- 数値属性のほかの既定値 (offset 0・比率は未指定) は何も足さない値で、余白 24 だけが器の側から値を足す既定になっている
- 0.1.0-beta.2 まで公開済みで、「今までどおりに出る」で守る相手は契約導入前の実装ではなく beta の利用者に移っている
- Loading は Dialog と同じ属性を共有する (core/ADR-0022)。既定ローディング (引数なしで出すライブラリ同梱のスピナー) も、Loading の一括設定で余白を渡せる。Toast は中身に余白が添付されていなければ契約既定値を使う
- 既定 Toast (メッセージだけで出すライブラリ同梱のピル) には、利用者が余白を渡す口が無い (Toast の一括設定にも余白の項目は無い)。カスタム Toast は中身への添付で余白を付けられる
- 契約既定値を 0 にすると、既定 Toast は 24 下がって下端が可視領域の下端から 80 の位置になり、Material のボトムナビ (80dp) の上端にちょうど接する。長いメッセージは画面の左右の端まで広がる

前提: 既定 Toast は利用者から余白を受け取る口を持たない。公開は beta の段階にある。

## Decision

余白の契約既定値を全辺 0 にする。Dialog・Loading・カスタム Toast は、余白を指定しなければ基準領域の端まで使う。

既定 Toast だけは、ライブラリが同梱のピルに従来と同じ余白 (全辺 24) を持たせ、見た目を変えない。これは契約既定値の例外ではなく、同梱のコンテンツが自分の性質として余白を持つ扱いとする。利用者のカスタム View が添付で余白を付けるのと同じ位置づけである。

core/ADR-0008 の決定のうち、既定値の乖離 3 件の余白 (全辺 24) を本決定で置き換える。覆いの色と基準領域の既定値の乖離を含む他の決定は維持する。

理由: 余白の既定が 0 なら、配置と基準領域の結果が基準の端にそのまま接して見え、利用者が挙動を読み取りやすい。数値属性の既定値がすべて「何も足さない」値に揃い、原典とも同じ既定になる。一方で既定 Toast は利用者が余白を渡せない。0 にすると長いメッセージが端に貼り付いても逃げ道が無く、下方向も既定配置がボトムバーを上回るようにした意図 (core/ADR-0032) から外れるため、同梱のピル自身に余白を持たせる。

## Alternatives Considered

- **余白の既定を全辺 24 のまま維持する (core/ADR-0008 に従う)** — 却下: 利用者は配置と基準領域の結果を「端から 24 引いて」読むことになり、Sample も検証のために全辺 0 を明示し続ける。維持の理由だった「契約導入前の実装の見た目を保つ」は、beta の公開後は守る相手が変わっている
- **Toast も既定・カスタムを問わず 0 に揃える** — 却下: 既定 Toast には余白を渡す口が無く、長いメッセージが画面の左右の端まで広がっても利用者に逃げ道が無い。下方向も 24 下がり、Material のボトムナビの上端にちょうど接する
- **Toast も 0 にし、既定配置の上方向オフセットを 80 から 104 に上げて縦位置を保つ** — 却下: 縦位置は保てるが、長いメッセージが左右の端に貼り付く問題は残る。ボトムバー回避の値の根拠 (core/ADR-0032) の書き直しも伴う
- **Toast の契約既定値として、既定・カスタムを問わず余白 24 を持つ** — 却下: 余白の契約既定値が Dialog・Loading の 0 と Toast の 24 の 2 つになる。カスタム Toast は添付で余白を付けられるので、契約既定値を分ける必要が無い

## Consequences

- 正: 何も指定しなければ、Dialog・Loading・カスタム Toast の配置の結果は基準領域の端に接し、配置と基準領域の効き方を見た目で確かめられる
- 正: 余白の契約既定値が原典と揃い、原典から移行するときに注意する「変わった既定値」が 1 件減る
- 正: 既定 Toast の見た目は変わらない
- 負: 大きな内容・fill・比率 1.0 のダイアログは、何も指定しなければ可視領域の端に接する。余白が欲しい利用者は自分で指定する
- 負: 公開済みの beta で余白を指定していない呼び出しは、先頭寄せ・末尾寄せの位置とクランプの結果が変わる (中央配置で内容が収まっていれば変わらない)
- 負: 既定 Toast とカスタム Toast で余白が異なり、何も指定しないカスタム Toast は既定 Toast より端へ 24 寄って出る。揃えたい利用者は余白を添付する

## Revisit When

- 既定 Toast に利用者が余白を渡す口 (一括設定の項目など) を足すとき
- 前提 (Context) が崩れたとき
