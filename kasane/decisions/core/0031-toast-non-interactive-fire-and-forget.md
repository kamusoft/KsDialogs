## Context

Toast の器はタッチを奪わない非モーダル派生とした (ADR-0030)。その上で、Toast 自身の面がタッチを受けるか (タップで即消し・カスタム View 内のボタン等) と、消え方・show の戻り値の意味論を決める必要がある。

- Android の OS ネイティブ Toast は非対話 (タッチは素通し・時間経過でのみ消える) であり、利用者の Toast 観はこれに根ざしている
- 「触れる通知」は Snackbar という別コンポーネントの慣習であり、ボタンや結果が欲しいケースは本ライブラリでは Dialog (配置属性で非モーダル的な配置も可能) が既に受け皿になっている
- Toast はページをまたいで生き残る (ADR-0030 の器は提示スタック不参加)。カスタム View に対話要素を置けたとしても、表示中にページが変わると「どのページの文脈で押されたのか」が壊れる — 非対話はページ横断要件からの必然でもある

## Decision

Toast は完全非対話とする。

- Toast の面もタッチ素通しとし、Toast の真下にあるページ要素も操作可能とする。カスタム View は表示専用 (対話要素を置いても反応しない)
- 消滅は時間経過でのみ起こる。タップで消す・スワイプで消す等の対話的な消し方は設けない
- show は戻り値なしの fire-and-forget とし、表示終了を待つ手段は契約に設けない
- duration は show 引数の ms 指定とし、既定は原典踏襲の 1500ms。原典 Android 実装にあった OS 由来の実質 3.5 秒クランプは継承しない (新実装では制約自体が消滅)

## Alternatives Considered

- **Toast の面はタッチを受ける (タップで即消し・カスタム View 内のボタン可)** — 却下: Toast の面の下だけページが操作不能になり「ページの要素を妨げない」要件が弱まる。Snackbar 寄りの別物になって OS 慣習の Toast 観からずれる。タップ通知・消し方の口で API が膨らむ。そしてページをまたいで生き残る Toast では対話要素のページ文脈が壊れる。対話可能 Toast が将来必要になれば opt-in の追加として互換を壊さず入れられる (逆方向 — タッチ受けから素通しへの変更 — は破壊的)

## Consequences

- 正: 「ページの要素を妨げない」が Toast の真下まで含めて完全に成立する
- 正: show が void + duration 引数だけの最小 API で確定する
- 負: カスタム View の自由度は表示専用に限定される (Undo つき通知のような対話型は本ライブラリの Toast では作れない。Dialog が受け皿)
- 派生: 対話可能 Toast は将来の opt-in 拡張の余地として残る
- 実装で判明した帰結 (出典: 実装結果): show が戻った後の失敗 (factory の例外・View の実体化失敗・器の取り付け失敗) は呼び出し元へ返せないため、「警告ログを出してその表示だけを破棄し、後続表示は継続する」という受理後の失敗モデルが契約に必要になった (dialog-contract の失敗モデル 3 段階のうちの 1 つ)
