## Context

ios/ADR-0002 では、器に載せた SwiftUI の中身に安全領域を届ける範囲を決めた。対象は、窓全体を基準にして端に付けた軸で、器と窓の安全領域が重なる分である。器の大きさは、安全領域を受け取らないときと同じにする。端に付けた中身は、器の内側で安全領域を避けるか、標準の書き方で無視するかを選べる、とした。

この形は、安全領域の分だけ縮められる中身を前提にしていた。文言とボタンを並べた中身のように縮まない中身では、使える高さが重なりの分だけ足りなくなる。SwiftUI は、収まらない中身を安全領域の内側の中央に置く。そのため、はみ出しが前後に半分ずつ割れ、中身は重なりの半分だけ内側へずれる。下端に付けると、ホームインジケータの領域 34 の半分の 17 だけ上がる。上端では 59 の半分の 29.5 だけ下がる。一番外側で安全領域を無視する指定を付けても、下端では位置が変わらない。

ColorAnalyzer の KMP 版の「下の確認」(窓の下端に付けた、高さが中身で決まる帯) は、0.1.0-beta.5 でこの形になった。beta.4 までの、窓の下端にぴったり付く見え方から変わった。アプリ側には位置を戻す手段が無く、ColorAnalyzer のオーナーはこの見え方を許容しなかった。半分だけずれる見え方は、安全領域を避けたことにも無視したことにもならない。どの中身にとっても望まれない並び方である。

前提: SwiftUI のホストの中で、はみ出す軸の中身を器の内側の辺にそろえて置けば、縮まない中身は器いっぱいに置かれ、縮められる中身は今までどおり安全領域の内側に収まる。中身から読める位置 (geometry) も描画と一致する。試作の実測で、はみ出す軸にだけそろえを効かせる形で成り立つことを確かめた。

## Decision

iOS の器に載せた SwiftUI の中身が、窓全体を基準にして端に付けた軸で安全領域の内側に収まらないときは、その軸で器の内側の辺 (下端に付けたなら上の辺、上端なら下の辺) にそろえ、器いっぱいに置く。器 (有効領域で頭打ちになる) より大きい中身も同じく内側の辺にそろえ、付いた側 (窓の端の外) へはみ出させる。収まる中身の並び方は ios/ADR-0002 のままにする。公開 API は増やさない。

範囲は、ios/ADR-0002 が安全領域を届ける範囲と同じにする。SwiftUI で書かれた Dialog・Loading・Toast の中身 (KMP の Swift 面から登録したものを含む) で、窓全体を基準にして片方の端に付けた軸が対象になる。両方の辺に付く軸 (全面) と中央の軸、窓全体以外の基準領域、UIView の中身は変えない。

理由: 縮まない中身は、器が大きくならない以上、安全領域を避けきれない。内側の辺にそろえれば、そうした中身は beta.4 までと同じく器いっぱいに置かれる。安全領域を無視する指定の有無で位置が変わらなくなり、ios/ADR-0002 が約束した「無視する指定の中身の見た目は変わらない」が縮まない中身でも成り立つ。既定の振る舞いのまま直るので、利用者は書き換えずに済む。縮められる中身と窓全体を覆う中身は、ios/ADR-0002 のとおり安全領域を受け取れる。

## Alternatives Considered

- **中身ごとに、安全領域を受け取らない指定を足す** — 却下。指定を付けた中身は beta.4 の見え方に戻るが、付けていない中身は半分ずれたまま残る。公開 API が 1 つ増え、core の約束にするなら Android 側との対応も考える必要がある
- **既定を beta.4 の振る舞い (安全領域を届けない) に戻し、受け取りたい中身だけ指定する** — 却下。ずれは無くなるが、ios/ADR-0002 の決定を実質的に取り消すことになり、公開 API も 1 つ増える
- **器より大きい中身は対象から外し、今の並び方 (前後に半分ずつはみ出す) のままにする** — 却下。例外が増え、収まらない中身の並び方を 1 つに約束できない
- **器より大きいときだけ、付いた側の辺にそろえる** — 却下。器に収まるかどうかで、そろえる辺の決まりが 2 段になる

## Consequences

- 正: 端に付けた縮まない SwiftUI の中身は、安全領域を無視する指定の有無にかかわらず、器いっぱいに置かれる。beta.4 までの見え方に頼っていたアプリは、書き換えずに元の見え方へ戻る
- 正: 縮められる中身と窓全体を覆う中身は、ios/ADR-0002 のとおり安全領域を受け取って避けられる
- 負: 縮まない中身は、端に付けてもシステムの領域を避けない。ホームインジケータやステータスバーとの重なりは中身の側で避ける必要がある (余白を足す・縮められる形にする)
- 負: 器より大きい縮まない中身は、付いた側の窓の端の外へはみ出した分が見えない
- 負: 収まらない中身の並び方は、SwiftUI 標準の中央寄せではなく KsDialogs が決めた内側の辺へのそろえになる。SwiftUI の画面と同じ書き方をしても、収まらないときの位置は画面と違う
