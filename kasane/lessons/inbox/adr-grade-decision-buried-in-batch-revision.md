## ルール文

スペックレビュー指摘への対応で design に新しい Decision を追加・実質変更するとき、その Decision が ADR 候補基準 (公開 API の形・覆すコストが高い判断) に当たるなら、一括反映で確定させずオーナーに個別論点として提示し合意を得る。レビュー対応の改訂サマリに「新設した Decision 一覧 (ADR 級か否かの判定つき)」を明記し、ADR 級には合意の記録 (日付・選択肢と採否) を残す。

## 経緯

- 2026-08-18 add-layout-spec: 相方スペックレビューの「属性の置き場が未定」という指摘自体は正しかったが、その解決として選ばれた「VM 契約に置く」は複数の対抗案 (show 引数 / View 側属性) を持つ ADR 級の設計判断だった。18指摘の一括反映バンドルとして提案が承認されたため、オーナーはこの論点を個別に議論した認識がないまま実装が5グループ進行し、KMP 実装不能の発覚と合わせて設計差し戻しになった。指摘対応の「回答」が新しい設計判断を生む場合は、それを議論の入力として扱うべきで、確定として書き込んではいけない
