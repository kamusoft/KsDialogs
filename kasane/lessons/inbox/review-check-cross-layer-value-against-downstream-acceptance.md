## ルール文

ある層が別の層 (Native・bridge・下位モジュール) の入口へ値を渡し、その値で下位の分岐 (採用 / 棄却して次の取得元へ / 既定の経路へ) を意図的に選ばせる実装をレビューするときは、下位の入口が値を受け入れる条件 (棄却条件の一覧と判定順) を下位の実装で確認し、上位が渡しうる値ごとに「下位でどの分岐に入るか」を突き合わせる。上位の判定が下位の棄却条件より緩い、または上位が番兵として渡す値 (「可視領域に落とす」ための代用品など) が下位の最初の確認で外れるなら指摘する。テストがその経路を検証していると主張するときは、意図した分岐と外れた場合の分岐で結果が変わるホスト構成になっているか (偶然一致していないか) を確かめる。
