## ルール文

新規画面を追加する UI モックを承認ゲートに掛けるとき、画面単体の見た目に加えて遷移モデル (その画面への入り方・戻り方・完了時の行き先) をモックまたは brief に明記する。既存のナビゲーション設計 (自前 chrome / 標準 nav) で戻る手段が成立しない形態が1つでもあれば、承認前に解決策を確定する。

## 経緯

- 2026-08-18 add-layout-spec: レイアウトデモの属性調整パネルは appbar にタイトルと Show ボタンのみのモックで承認された。Android は system back があるため気づきにくいが、iOS には暗黙の戻る手段がなく、パリティ規約が4ルート共通の遷移解を要求するため設計判断としてオーナーに差し戻しになった。モック承認時に「この画面からどう戻るか」を一問確認すれば防げた
